# 仿真工具笔记 (Simulation and Tooling Notes)

## 概述

控制工程的仿真工具生态涵盖从快速原型设计到实时硬件在环测试的完整谱系。本文件记录主要仿真平台和工具的特点、使用场景、安装要点，以及控制工程师在仿真实践中需要遵循的基本原则。工具选择的核心权衡是易用性与保真度：Python Control 适合快速概念验证，MATLAB/Simulink 适合中保真度设计和代码生成，硬件在环 (HIL) 和实时仿真器（如 dSPACE、NI PXI、Speedgoat）适用于最终的部署前验证。

## 仿真平台

### MATLAB / Simulink / Control System Toolbox

**定位**：控制工程仿真的事实标准。覆盖从本科教学到航空 DO-178C 代码生成的全谱系。Simulink 的图形化建模对控制系统可视化设计价值极大。

**核心工具箱**：Control System Toolbox（传递函数、状态空间、频域分析、LQR/H_inf）、Simulink Control Design（MPC 设计、时域和频域验证）、Robust Control Toolbox（mu 综合、LMI 求解）、System Identification Toolbox（ARX/ARMAX/子空间辨识、频率响应估计）、Model Predictive Control Toolbox（MPC 设计与部署）、Reinforcement Learning Toolbox（Q 学习、DDPG、SAC 与 Simulink 集成）

**安装要点**：MATLAB 2023b+ 的安装大小约为 3-30 GB（取决于工具箱选择）。学术版通过 campus license 安装。推荐安装：基础 MATLAB + Simulink + Control System Toolbox + System ID Toolbox + Robust Control Toolbox（约 8 GB）。Simulink 代码生成需要 Simulink Coder + Embedded Coder（额外 3 GB）。

**仿真实践**：初学者从使用 `ss`, `tf`, `bode`, `step`, `rlocus` 命令开始。中级用户构建 Simulink 模型运行闭环仿真，改变 PID 参数观察响应变化。高级用户结合 Optimization Toolbox 进行参数扫描和自动调参。

### Python Control 库

**定位**：开源控制仿真的主要选择。与 MATLAB Control Toolbox 功能高度对应，适合教学和快速原型设计。对于需要 Python 生态（数据分析、机器学习）的控制项目是理想选择。

**核心库**：`control` (python-control) 提供 TransferFunction、StateSpace、bode_plot、root_locus、step_response、nichiolls、lqr、hinfsyn、sisotool 等方法。`scipy.signal` 提供信号处理功能，`numpy` 提供矩阵运算，`matplotlib` 提供绘图。`slycot`（可选 Fortran 包装）提供更快的 Riccati 方程求解和频域分析。

**安装指南**：`pip install control`。若需 slycot 加速，从 conda-forge 安装：`conda install -c conda-forge slycot control`。推荐使用 Anaconda 环境管理，Python 版本不低于 3.9。验证安装：`python -c "import control; print(control.__version__)"`。

**仿真示例**（一个简单的闭环系统）：

``import control as ct
import matplotlib.pyplot as plt
G = ct.TransferFunction([1], [1, 2, 1])
K = 2.0
T = ct.feedback(K*G, 1)
t, y = ct.step_response(T)
plt.plot(t, y)``

### OpenAI Gymnasium 与 MuJoCo

**定位**：强化学习和数据驱动控制方法的仿真环境标准。Gymnasium 提供了统一的环境接口（继承 gym.Env），MuJoCo 提供高效的多体动力学物理仿真。

**适用场景**：机器人控制策略的端到端训练与评估、接触动力学和摩擦效应的仿真、RL 算法的 benchmark 测试。

**核心工具**：Gymnasium（标准 RL 接口，版本 0.28+）、MuJoCo（物理引擎，MuJoCo 2.2+）、DMC (dm_control, DeepMind 的 MuJoCo 包装器)。安装：`pip install gymnasium mujoco`。dm_control 需额外安装。

**仿真原则**：训练阶段的仿真使用 MuJoCo 的较高速仿真（enable visual=False, 使用更快积分器），评估时切换到标准保真度。仿真步长对结果敏感，推荐的 MuJoCo 控制频率为 50-500 Hz。

### 仿真实战原则

**激励信号的选择**：系统辨识需要充分的频率覆盖。推荐使用 PRBS (Pseudo-Random Binary Sequence) 或 Chirp（扫频）信号。幅值应覆盖系统工作范围的 30-80% 以达到足够的信噪比，但不超过系统的线性工作范围。评价激励质量的指标：频谱分析——激励信号的功率谱应在感兴趣的频带内平坦（变化不超过 3 dB）。

**仿真步长选择**：连续系统仿真的步长应小于系统最小时间常数的 1/5。例如一个系统有 0.1 s 的时间常数，仿真步长不应大于 0.02 s。对于数字控制仿真，仿真步长通常比控制周期小 10-20 倍（例如控制周期 0.01 s → 仿真步长 0.0005-0.001 s）。

**模型验证的"黄金法则"**：不要在用于训练模型的数据上评估模型性能（resubstitution validation 是禁忌）。使用独立的验证集。对于时间序列数据，验证数据应来自不同于训练数据的时间段（以避免时序自相关性）。

**蒙特卡洛仿真**：在不确定参数下评估控制系统鲁棒性的标准方法。参数采样数 N 的选取：对于 95% 的置信水平，N >= 60（大样本近似），若要检测低概率事件（P < 0.01），需要 N >= 1000。

**硬件在环 (HIL) 的基本时间要求**：HIL 仿真器的实时执行周期应不小于被控系统最小时间常数的 1/10。例如被控系统有 10 ms 的最小时间常数→HIL 步长 1 ms（1000 Hz）。超出此限制意味着 HIL 仿真不能真实反映系统在硬件上的行为。
