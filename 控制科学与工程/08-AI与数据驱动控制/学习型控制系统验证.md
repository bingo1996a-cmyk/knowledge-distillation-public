# 学习型控制系统的验证 (Verification of Learning-Enabled Control Systems)

## 定位

学习型控制系统验证是形式化方法、鲁棒控制理论与机器学习可解释性交叉形成的研究领域，目标是回答根本工程问题：如何证明一个包含神经网络组件（策略网络、价值网络、状态估计网络）的闭环控制系统在所有可能场景下都满足安全规范？传统控制验证（增益裕度、相位裕度、Lyapunov 稳定性证明）假设控制器具有已知的解析形式，而神经网络的非线性、高维性、黑箱特性使得经典工具无法直接应用。验证方法分为确定性方法（可达集分析、SMT/MILP 求解、Barrier Certificate）和概率方法（统计模型检验、Conformal Prediction、PAC-Bayes 边界），两者在完备性、可扩展性和保守性之间有不同的权衡。

## 核心问题

验证的根本困难是深度神经网络的高度非线性导致状态空间分割极其复杂。对于一个 m 层 ReLU 网络、每层 n 个神经元，可能的激活模式数量为 O((2^n)^m)——天文数字。具体工程问题包括：如何处理连续状态空间中的无穷多可能状态；如何验证策略在最坏情况扰动下的安全性；如何将验证结果与控制系统设计的工程语言（裕度、鲁棒性）对接；验证结果如何支持认证和许可流程（如航空 DO-178C、医疗 IEC 62304）；以及策略在线更新后的重新验证问题。

从控制工程视角看，验证的终极目标是回答：对于系统 $\dot{x} = f(x,\pi_\theta(x),w)$，安全集 $\mathcal{S}$，初始集 $\mathcal{X}_0$，是否有 $\forall t \geq 0, \forall x_0 \in \mathcal{X}_0, \forall w \in \mathcal{W}: x(t) \in \mathcal{S}$？

## 基本模型

### 可达集分析 (Reachable Set Analysis)

计算系统轨迹的集合而非单条轨迹。前向可达集定义为所有初始状态和扰动下可达状态的集合：

$$ \mathcal{R}_{t+1} = \{ x' = f(x, \pi_\theta(x), w) \;|\; x \in \mathcal{R}_t, w \in \mathcal{W} \} $$

计算方法包括：

- **Zonotope / Polytope 传播**：将状态集表示为 zonotope（中心对称多面体），通过每层网络的 affine + ReLU 运算传播。ReLU 操作将 zonotope 划分为多个子区域，zonotope 数量指数增长，需使用 over-approximation（如 DeepZ）牺牲精度换取计算可行
- **混合整数规划 (MILP)**：将每个 ReLU 神经元的激活模式编码为 MILP 约束。优点是精确，但求解时间随神经元数量指数增长。适用于小规模网络
- **α,β-CROWN**：基于线性松弛的 bound propagation，使用激活函数的线性松弛参数 α，通过优化 α 收紧边界。目前在 VNN-COMP 竞赛中表现优异

### Barrier Certificate (屏障证书)

为系统寻找函数 $B(x)$ 满足：$B(x_0) \leq 0 \; \forall x_0 \in \mathcal{X}_0$，$B(x) > 0 \; \forall x \in \partial \mathcal{U}$，$\dot{B}(x) \leq 0 \; \forall x \in \mathcal{X}$。满足条件则证明系统永远无法从 $\mathcal{X}_0$ 到达不安全集 $\mathcal{U}$。对于学习型控制系统，$B(x)$ 的搜索通常表示为 SOS 规划或使用神经网络表示并通过对抗训练求解。Barrier Certificate 的优势是不显式计算可达集，但搜索问题本身非凸且可能无解。

### 统计验证 (Statistical Verification)

以概率方式回答安全属性。包括：

- **统计模型检验 (SMC)**：对系统轨迹进行蒙特卡洛采样，使用假设检验判断 $P(\text{safety violation}) \leq \epsilon$。计算成本线性增长，但不能提供确定性保证
- **Conformal Prediction**：构造校准的不确定性集，提供有限样本的分布无关覆盖保证
- **PAC-Bayes 边界**：为学习策略提供 $(\epsilon,\delta)$ 边界：$P(\text{性能退化超过} \epsilon) \leq \delta$

### 运行时监控 (Runtime Monitoring / Runtime Assurance)

当离线验证不可行时，在系统运行过程中持续检测不安全状态并触发安全操作。核心组件：

1. **Shield**：策略输出通过已验证的安全滤波器（如 CBF-QP）
2. **Conformance Monitor**：检测系统行为是否偏离训练分布（AE 重建误差、OCSVM 异常检测）
3. **Fallback Mechanism**：当监控器触发时切换到预设安全策略（阻尼、紧急停机、保守策略）

运行时监控的核心平衡在于灵敏度：false negative rate（漏报率）应尽可能接近零，即使以升高 false positive rate 为代价。

## 关键概念

### 完备性-可扩展性权衡

验证方法在完备性和可扩展性之间呈 Pareto 前缘：MILP/SMT 完备但仅可扩展至数十神经元；Zonotope over-approximation 不完备，可扩展至数百至数千神经元；Statistical methods 统计完备，可扩展至任意大规模网络。工程上：安全关键等级高但网络规模小的系统（10-100 神经元），使用形式化验证；大规模网络（$10^6+$ 神经元），接受统计验证 + 运行时监控的组合方案。

### Local vs Global Robustness

Local robustness 验证特定输入邻域内的鲁棒性，可计算但不能保证全局安全。Global robustness 对全状态空间验证，通常不可解，可对分段线性网络的每个线性区域分别验证。工程实践：local robustness verification for critical states + statistical testing for global behavior。

### 开环验证 vs 闭环验证

开环验证检查神经网络映射 $\pi_\theta(x)$ 在单步是否产生安全动作；闭环验证检查策略作为反馈控制器时系统的长期行为。开环安全的网络可能产生不安全的闭环行为（链式不安全行为）。闭环验证的计算复杂度比开环高 O(T) 到 O(|S|^T) 倍（T 为时间 horizon）。

### 验证引导的训练 (Verification-Guided Training)

在训练过程中纳入验证约束：将 bound propagation 结果作为正则项加入训练目标；在训练中生成违反安全的对抗性输入；修改网络权重使传播边界更紧；使用 SMT 求解找到违反条件的输入并加入训练集。这类方法显著提高策略的可验证性，但训练成本增加 2-10 倍。

## 工程判断

- **验证深度与安全等级的对应**：参考 ISO 26262 (汽车) / DO-178C (航空) 的 ASIL/DAL 等级。ASIL A（低风险）可仅做统计验证（1000 次随机测试无失效）；ASIL D（高风险）需要形式化可达集分析或屏障证书验证

- **验证计算预算估计**：对于 $[64,64]$ 隐层策略网络，10 步 horizon 的 MILP 验证约需 10 秒-10 分钟。推荐：$< 500$ 神经元 -> MILP/SMT；$500-5000$ 神经元 -> Zonotope 传播；$> 5000$ 神经元 -> 统计方法 + 运行时监控

- **可达集分析的 horizon 选取**：验证 horizon $T = 3-5\tau$（$\tau$ 为最慢时间常数）。更高的 T 导致计算成本指数增长，验证收益递减

- **运行时监控器阈值设计**：收集 10,000 个正常状态样本，计算重构误差分布，设定阈值在 95-99% 分位数。阈值过低（$< 90%$）导致过多假阳性，过高（$> 99.9%$）可能漏检

- **Fallback 策略设计原则**：fallback 应是最保守的已知安全策略。机器人：保持位置并等待救援；车辆：减速停止并靠边；过程控制：保持最后安全阀位并报警。从检测到 fallback 执行的延迟应小于系统最小稳定时间（通常 $< 50$ ms 用于快速系统，$< 500$ ms 用于慢速系统）

- **验证成本与安全收益的平衡**：一个完整的验证流程（可达集分析 + SMC + 运行时监控）的工程成本约为策略开发成本的 2-5 倍。对于安全关键系统（ASIL C/D），验证是强制不可省略的；对于非安全关键系统（ASIL A），可只做 SMC + 简单的运行时异常检测

- **策略更新后的增量验证**：策略网络参数更新后，完整重验证的计算成本不可接受。增量验证技术：只验证网络层权值变化超过阈值（如 5%）的神经元影响的状态空间区域；利用网络 Lipschitz 常数变化量推导安全集的变化范围

## 常见误区

- **等到策略训练完成后再做验证**："验证 by design"远优于"事后验证"。如果在训练中不考虑验证约束，训练出的策略很可能使形式化验证无法进行（网络权重分布导致 bound propagation 极度松散）。验证友好的网络结构（如 Lipschitz 正则化、小权重、浅层网络）应在训练初始就考虑

- **认为"测试中没发生事故"等价于"系统安全"**：神经网络的黑箱特性使得"无失效测试"不能作为安全性证据。一个测试覆盖不充分的策略可能在部署后的第一个未见场景中完全失效。形式化验证与统计测试是互补的，不可相互替代

- **忽视传感器噪声和执行器误差对验证结果的影响**：形式化验证通常假设状态估计是精确的，但实际系统中传感器噪声和状态估计误差会导致验证边界失效。验证应在状态估计不确定集上做，而非单点状态上做

- **混淆策略网络的 Lipschitz 常数与系统闭环稳定性**：一个低 Lipschitz 常数的策略网络（小输出变化对应小输入变化）不保证闭环系统稳定。系统稳定性还依赖于动力学模型和策略的组合特性。Lipschitz 常数仅为验证提供一个充分但非必要的条件

- **低估运行时监控的计算开销**：在嵌入式平台上运行神经网络异常检测器的计算开销可能占整个控制周期的 10-50%。评估监控器的实时性是否满足控制周期的 10% 原则，否则需为监控器使用更轻量级的方法（如 k-d 树、高斯混合模型）
