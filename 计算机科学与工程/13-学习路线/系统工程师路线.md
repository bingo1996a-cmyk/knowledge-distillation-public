# 系统工程师路线

## 1. 一句话定义

本路线面向目标是基础架构/SRE/系统开发的工程师，强调底层系统知识、分布式思维和性能调优能力。

## 2. 核心问题

- 系统工程师和软件工程师的核心区别是什么？
- 什么样的知识积累能支撑处理复杂的生产环境问题？
- 如何从"会用基础设施"升级为"理解并建设基础设施"？

## 3. 五阶段路线

### 阶段一：单机系统基础

| 技能 | 要点 |
|------|------|
| Linux 深入 | 文件系统（inode）、进程（fork/exec）、信号、管道 |
| C 语言 | 指针、内存管理、系统调用 |
| 计算机组成 | CPU 架构、缓存、MMU、中断 |
| 操作系统 | 虚拟内存、进程调度、文件系统 |

### 阶段二：网络与协议

| 技能 | 要点 |
|------|------|
| TCP/IP 深入 | 三次握手/四次挥手、拥塞控制、TIME_WAIT |
| HTTP/HTTPS | HTTP/1.1 vs HTTP/2 vs HTTP/3 |
| DNS | 解析流程、记录类型 |
| 抓包分析 | tcpdump/Wireshark 熟练使用 |

### 阶段三：分布式系统

| 技能 | 要点 |
|------|------|
| 共识算法 | Raft——理解 Leader 选举、日志复制 |
| 复制与分片 | 主从复制、一致性哈希 |
| CAP 与一致性 | 线性一致、最终一致、因果一致 |
| 分布式故障模式 | 网络分区、部分失效、拜占庭故障 |

### 阶段四：云原生基础设施

| 技能 | 要点 |
|------|------|
| K8s 深入 | Pod 调度、网络策略、存储编排、Operator 模式 |
| 基础设施即代码 | Terraform/Pulumi |
| 可观测性 | Prometheus + Grafana + Jaeger（指标、日志、追踪）|
| CI/CD | 流水线设计、GitOps |

### 阶段五：性能工程

| 技能 | 要点 |
|------|------|
| CPU 性能 | perf、火焰图、缓存优化 |
| 内存优化 | 减少分配、内存池、内存泄漏检测 |
| IO 性能 | 磁盘 IOPS、IOWAIT、异步 IO |
| 网络性能 | 延迟优化、连接池、零拷贝 |

## 4. 系统工程师 vs 软件工程师

| 维度 | 系统工程师 | 软件工程师 |
|------|-----------|------------|
| 关注 | "系统如何工作" | "用户能做什么" |
| 日常 | 性能调优、故障排查、容量规划 | 功能开发、代码重构 |
| 深度 | 向下到 OS/硬件 | 向上到业务逻辑 |
| 广度 | 横向覆盖网络/存储/计算 | 按功能模块深入 |

## 5. 工程实践

- 从零实现一个简易的 Web Server（理解 socket 编程和 HTTP 协议）
- 用 Docker 和 K8s 搭建完整的基础设施环境
- 故意注入故障测试系统的容错能力（Chaos Engineering）
- 用 perf/eBPF 分析一个真实应用的性能瓶颈

## 6. 与其他主题的关系

| 相关主题 | 关系 |
|----------|------|
| 操作系统 | 系统工程师的核心知识层 |
| 计算机网络 | 排查网络问题是日常核心工作 |
| 数据库 | 分布式数据库是系统工程师维护的核心系统 |
| 安全 | 基础设施安全是系统工程师职责 |
