# 测试与验证

## 1. 一句话定义

软件测试通过运行程序来发现缺陷，形式验证通过数学证明来保证正确性，二者是软件质量保证的两条互补路径。

## 2. 核心问题

- 如何以最小成本覆盖最多风险？
- 什么应该自动化测试，什么应该人工检查？
- 测试金字塔如何在实践中落地？

## 3. 知识框架

| 层次 | 验证范围 | 典型工具/方法 |
|------|----------|---------------|
| 单元测试 | 单个函数/类 | pytest、JUnit、GoogleTest |
| 集成测试 | 模块间交互 | 测试数据库、HTTP 客户端 mock |
| 端到端测试 | 完整用户流程 | Playwright、Selenium |
| 性能测试 | 吞吐量、延迟 | JMeter、k6 |
| 形式验证 | 数学正确性证明 | TLA+、Alloy、Coq |

## 4. 关键概念

- **测试金字塔**：大量单元测试（快、便宜）+ 中等集成测试 + 少量 E2E 测试（慢、贵）
- **测试驱动开发（TDD）**：红灯（写失败测试）→ 绿灯（最小实现通过测试）→ 重构 → 循环
- **测试覆盖率**：行覆盖 vs 分支覆盖 vs 条件覆盖——覆盖率是必要条件不是充分条件
- **Fuzzing（模糊测试）**：向程序输入随机/半随机数据寻找崩溃——现代系统安全测试的核心方法
- **Mock vs Stub vs Fake**：Mock 验证行为（是否被调用），Stub 提供固定返回值，Fake 提供简化实现

## 5. 典型方法

### 5.1 测试金字塔

```
        /\
       /E2E\        少量，验证关键用户路径
      /------\
     /  集成  \      中等，验证模块交互
    /----------\
   /   单元测试  \    大量，验证函数/类逻辑
  /--------------\
```

### 5.2 形式验证在工业界的应用

| 领域 | 方法 |
|------|------|
| 分布式协议 | TLA+（AWS 用于 DynamoDB、S3 等关键服务）|
| 硬件设计 | 模型检验广泛用于芯片验证 |
| 密码协议 | 形式化安全性分析 |
| 操作系统微内核 | seL4——完全形式验证的内核 |

## 6. 经典问题

- 测试的"冰激凌锥"反模式——E2E 太多、单元测试太少
- 脆弱的测试——过度依赖 UI 导致测试频繁失败
- Flaky Test——同样的代码和环境下有时通过有时失败
- 测试数据管理——如何创建和维护有效的测试数据集

## 7. 工程实践

- 为新功能先写测试，持续补充已有功能的测试覆盖
- 在 CI 中集成自动测试和覆盖率检查
- 使用 Property-Based Testing（如 Hypothesis）覆盖更多的边界情况
- 实践 mutation testing 评估测试套件的有效性
