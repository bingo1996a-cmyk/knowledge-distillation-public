# 软件工程

## 1. 一句话定义

软件工程是将系统化、可度量的方法应用于软件开发、运行和维护的工程学科，解决从个人小项目到大规模协作系统的开发问题。

## 2. 核心问题

- 如何管理和控制软件开发的复杂性？
- 如何在质量、速度、成本之间找到平衡？
- 如何确保软件在长期演化中保持可维护性？

## 3. 知识框架

| 子领域 | 核心内容 | 关键产出 |
|--------|----------|----------|
| 需求工程 | 需求获取、分析、规格说明、验证 | 需求文档、用户故事 |
| 软件架构 | 架构风格、架构决策、质量属性 | 架构文档、设计图 |
| 设计模式 | 创建型、结构型、行为型模式 | 可复用的设计方案 |
| 测试与验证 | 单元测试、集成测试、系统测试、形式验证 | 测试用例、覆盖率报告 |
| DevOps | 持续集成、持续部署、基础设施即代码 | 流水线、部署脚本 |
| 软件项目管理 | 过程模型、估算、风险管理、团队协作 | 计划、迭代回顾 |

## 4. 关键概念

- **模块化与信息隐藏**：通过接口分离实现细节，降低耦合
- **内聚与耦合**：高内聚低耦合是良好设计的核心原则
- **SOLID 原则**：面向对象设计的五个基本原则
- **技术债**：为短期速度牺牲长期质量所累积的隐性成本
- **敏捷 vs 瀑布**：适应变化 vs 按计划执行，两种主要过程哲学

## 5. 典型方法

### 5.1 经典架构风格

| 风格 | 特点 | 适用场景 |
|------|------|----------|
| 分层架构 | 逐层调用，单向依赖 | 企业应用 |
| 微服务 | 服务独立部署，轻量级通信 | 大规模分布式系统 |
| 事件驱动 | 发布-订阅，异步解耦 | 实时数据处理 |
| CQRS | 读写分离模型 | 高并发查询系统 |

### 5.2 测试金字塔

```
        /\
       /E2E\         少量端到端测试
      /------\
     /  集成  \       中等数量集成测试
    /----------\
   /   单元测试   \    大量单元测试
  /--------------\
```

## 6. 经典问题

- 需求变化导致的架构演变
- 遗留系统现代化改造
- 技术选型的决策框架
- 分布式系统中的测试复杂性
- 团队规模与沟通成本的非线性增长

## 7. 工程实践

- 为实际项目建立 CI/CD 流水线（如 GitHub Actions）
- 使用代码审查（Code Review）提升团队代码质量
- 对遗留代码逐步补充测试覆盖
- 实践测试驱动开发（TDD）或行为驱动开发（BDD）
