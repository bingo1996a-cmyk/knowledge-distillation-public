# 写作规范

## 1. 一句话定义

本文件规定知识库中所有 Markdown 页面的编写标准、模板使用和质量要求。

## 2. 核心问题

- 如何保持全库页面结构一致？
- 如何确保内容质量可控？
- 不同类型页面应有什么区别？

## 3. 页面类型与模板

本库区分 6 类页面，每类有不同的写作侧重点：

| 页面类型 | 用途 | 模板侧重 | 示例 |
|----------|------|----------|------|
| 总览页 | 建立领域地图 | 全景框架 + 关系描述 | 人工智能总览.md |
| 概念页 | 解释核心术语 | 精确定义 + 直观理解 + 例子 | 虚拟内存.md |
| 方法页 | 解释算法或机制 | 问题→思路→步骤→复杂度 | 动态规划.md |
| 系统页 | 描述工程系统 | 架构 + 核心机制 + 工程考量 | Kubernetes.md |
| 文献页 | 管理论文教材 | 文献元信息 + 核心贡献 + 影响 | 经典论文索引.md |
| 路线页 | 规划学习路径 | 目标人群 + 阶段划分 + 推荐资料 | 研究生科研路线.md |

## 4. 通用模板（10 节标准结构）

```markdown
---
title: <页面标题>
category: <所属一级目录>
tags: [<标签列表>]
status: draft | review | stable
version: <语义版本号>
created: <创建日期>
updated: <更新日期>
source_level: 教材 | 论文 | 官方文档 | 工程经验 | 待验证
---

# <页面标题>

## 1. 一句话定义
（不超过 3 句话）

## 2. 核心问题
（该主题解决什么问题）

## 3. 知识框架
（用表格组织核心内容）

## 4. 关键概念
（解释核心术语及其关系）

## 5. 典型机制/算法/系统
（选择 1-3 个代表性内容展开）

## 6. 经典问题
（该领域的经典问题或案例）

## 7. 工程实践
（至少列出 1 个可操作方向）

## 8. 与其他主题的关系
（库内关联主题及关系说明）

## 9. 推荐资料
（教材 > 论文 > 官方文档）

## 10. 待核查问题
（不确定内容必须显式标注）
```

## 5. 内容质量要求

### 5.1 必须包含

| 字段 | 要求 |
|------|------|
| 定义 | 不超过 3 句话，清晰准确 |
| 核心问题 | 说明该主题解决什么问题 |
| 知识框架 | 用表格组织，一目了然 |
| 关键概念 | 不堆术语，要解释关系 |
| 工程实践 | 至少列出 1 个可操作方向 |
| 推荐资料 | 教材、论文、官方文档优先 |
| 待核查 | 不确定内容必须显式标注 |

### 5.2 禁止内容

| 禁止项 | 原因 |
|--------|------|
| 无来源的历史断言 | 容易产生伪知识 |
| 不标注版本的技术描述 | 软件生态变化快 |
| 大段复制教材或博客 | 版权与可维护性问题 |
| 空泛评价 | 不能支持学习和科研 |
| 没有上下文的代码片段 | 难以复用 |

## 6. 引用规范

- 教材：作者.《书名》. 出版社, 版本/年份
- 论文：作者. "标题". 会议/期刊, 年份
- 官方文档：项目名 + 版本号 + URL（如有）
- RFC/标准：编号 + 标题 + 年份
- 引用标注使用 `source_level` 字段区分可信度

## 7. 页面前置元数据（YAML Front Matter）规范

| 字段 | 必填 | 说明 |
|------|------|------|
| title | 是 | 页面标题 |
| category | 是 | 所属一级目录名称 |
| tags | 是 | 标签列表，用于检索 |
| status | 是 | draft / review / stable |
| version | 是 | 语义版本号 |
| created | 是 | 创建日期 |
| updated | 是 | 最后更新日期 |
| source_level | 是 | 主要依据的可信度等级 |
