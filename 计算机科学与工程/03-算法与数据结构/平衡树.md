# 平衡树

## 1. 一句话定义

平衡树（Balanced Tree）通过自平衡操作（旋转、变色、分裂合并）保证树的高度为 O(log n)，从而确保查找、插入、删除操作的对数时间复杂度。

## 2. 核心问题

- 如何在插入和删除后快速恢复平衡？
- 不同平衡策略的工程取舍是什么？
- 磁盘场景下为什么需要多叉树而非二叉树？

## 3. 知识框架

| 结构 | 平衡策略 | 典型应用 |
|------|----------|----------|
| AVL 树 | 严格平衡（高度差 ≤ 1）| 查找密集型场景 |
| 红黑树 | 宽松平衡（最长 ≤ 2×最短）| Java TreeMap、C++ std::map |
| B 树 | 多叉、节点可存多个键 | 数据库索引、文件系统 |
| B+ 树 | B 树变体，数据全在叶节点 | MySQL InnoDB |
| 跳表 | 概率平衡，多层索引 | Redis Sorted Set |

## 4. 关键概念

- **旋转（Rotation）**：左旋/右旋——在保持 BST 性质的前提下改变树结构，是 AVL 和红黑树的核心操作
- **红黑树五性质**：根黑、叶黑、红节点子必黑、黑高相等——保证最长路径 ≤ 2× 最短路径
- **B 树阶数**：每个节点最多 m 个子节点，至少 ⌈m/2⌉ 个（根除外）——m 越大树越矮，适合磁盘
- **B+ 树 vs B 树**：B+ 树数据全在叶节点 + 叶节点链表串联——支持高效范围查询

## 5. 典型机制

### 5.1 红黑树插入的三种修复情况

```
Case 1: 叔叔是红色 → 变色（父黑、叔黑、爷红），向上传播
Case 2: 叔叔是黑色（三角型）→ 旋转父节点变成 Case 3
Case 3: 叔叔是黑色（直线型）→ 旋转爷节点 + 变色
```

### 5.2 主流平衡结构对比

| 结构 | 平衡方式 | 查找 | 插入 | 空间 | 特点 |
|------|----------|------|------|------|------|
| AVL | 旋转（严格）| 最快 | 较慢 | 平衡因子 | 适合读多写少 |
| 红黑树 | 旋转+变色（宽松）| 快 | 快 | 颜色位 | 平衡读写，默认首选 |
| 跳表 | 随机层数 | 快 | 快 | 指针多 | 实现简单，并发友好 |
| B+ 树 | 分裂合并 | O(log n) | O(log n) | 磁盘块 | 数据库索引标准 |

## 6. 经典问题

- 为什么数据库用 B+ 树而非常规二叉平衡树——磁盘 IO 以页为单位，多叉树减少高度
- 跳表 vs 平衡树的并发优势——跳表无需全局旋转，锁粒度更细
- 持久化数据结构中的平衡树变体
