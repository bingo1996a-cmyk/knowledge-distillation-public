# 哈希表

## 1. 一句话定义

哈希表（Hash Table）通过哈希函数将键映射到数组索引，实现 O(1) 期望时间的插入、删除和查找，是最重要的基础数据结构之一。

## 2. 核心问题

- 如何将任意类型的键均匀地映射到固定大小的数组？
- 两个键映射到同一位置时（冲突）如何处理？
- 如何在空间和时间之间权衡？

## 3. 知识框架

| 主题 | 核心内容 | 代表性技术 |
|------|----------|------------|
| 哈希函数 | 将键映射为整数索引 | 模运算、乘法哈希、全域哈希 |
| 冲突解决 | 处理不同键映射到同一位置 | 链地址法、开放寻址 |
| 动态扩容 | 负载因子过高时自动扩容 | 渐进式 rehash |
| 安全哈希 | 抗碰撞、抗原像 | SHA-256、SipHash |

## 4. 关键概念

- **哈希函数**：h(key) → index，好的哈希函数应满足均匀分布和高效计算
- **负载因子（Load Factor）**：α = n/m（元素数/槽位数）——α 过大时性能退化至 O(n)
- **冲突解决—链地址法**：每个槽位是一个链表/树，冲突元素串在同一链上——JDK HashMap 默认方式
- **冲突解决—开放寻址**：冲突时探查下一个槽位——线性探查（简单但易聚集）、二次探查、双重哈希
- **一致性哈希**：分布式场景中最小化扩容时的键迁移量——CDN 和分布式缓存的核心技术

## 5. 典型机制

### 5.1 HashMap 的核心操作

```
插入(key, value):
  index = hash(key) % capacity
  if 槽空: 直接放入
  else: 遍历链表/树 → 键相等则更新, 否则追加
  检查负载因子 → 超过阈值则扩容+rehash

查找(key):
  index = hash(key) % capacity
  遍历链表/树 → 找到返回, 否则不存在

删除(key):
  同查找 → 从链表/树中移除
```

### 5.2 冲突解决对比

| 方法 | 优点 | 缺点 |
|------|------|------|
| 链地址法 | 实现简单，删除容易 | 额外指针空间，缓存不友好 |
| 线性探查 | 缓存友好，无指针开销 | 一次聚集（Primary Clustering）|
| 二次探查 | 减少聚集 | 二次聚集（Secondary Clustering）|
| 双重哈希 | 接近理想的均匀分布 | 计算开销大 |

## 6. 经典问题

- 哈希碰撞攻击——攻击者构造大量同哈希键导致退化至 O(n)
- 动态扩容的时机和策略——redis 渐进式 rehash 避免卡顿
- 布隆过滤器——用多个哈希函数实现空间高效的"可能存在"查询
