# 云计算

## 1. 一句话定义

云计算通过网络按需提供可弹性伸缩的计算资源（计算、存储、网络），将基础设施从资本支出转变为运营支出，支撑了现代互联网服务的规模化运行。

## 2. 核心问题

- 如何将物理资源高效地切分和共享给多个租户？
- 如何实现按需弹性扩缩容？
- 如何在不可靠硬件之上提供高可用的服务？

## 3. 知识框架

| 服务模型 | 提供的抽象 | 代表产品 |
|----------|------------|----------|
| IaaS（基础设施即服务）| 虚拟机、网络、存储 | AWS EC2、阿里云 ECS |
| PaaS（平台即服务）| 运行时、数据库、中间件 | Heroku、Google App Engine |
| SaaS（软件即服务）| 完整应用 | Gmail、Salesforce |
| FaaS（函数即服务）| 函数 + 事件触发 | AWS Lambda |
| CaaS（容器即服务）| 容器编排平台 | AWS EKS、GKE |

## 4. 关键概念

- **虚拟化**：Hypervisor（如 KVM）将物理机抽象为多个虚拟机；容器（如 Docker）在 OS 层隔离
- **弹性伸缩**：根据负载自动增减实例数——水平伸缩（加实例）vs 垂直伸缩（加资源）
- **按需付费**：只为实际使用的资源付费，降低成本门槛
- **区域与可用区**：区域（Region）地理独立，可用区（AZ）物理隔离但网络连通——实现高可用
- **不可变基础设施**：部署后不修改运行实例，改动通过重建实现

## 5. 典型机制

### 5.1 虚拟化 vs 容器化

| 特性 | 虚拟机 | 容器 |
|------|--------|------|
| 隔离级别 | 硬件级（Hypervisor）| OS 级（namespace/cgroup）|
| 启动时间 | 分钟级 | 秒级 |
| 密度 | 每主机数十个 | 每主机数百个 |
| 资源开销 | 每个 VM 需 Guest OS | 共享 Host OS 内核 |
| 安全性 | 强（硬件支持）| 较弱（共享内核）|

### 5.2 云原生技术栈

```
应用层：微服务、Service Mesh（Istio/Linkerd）
编排层：Kubernetes
运行时：容器（containerd/CRI-O）
基础设施：云提供商（AWS/GCP/Azure）或裸金属
```

## 6. 经典问题

- 资源超额分配（Overcommit）导致性能抖动
- 实例间延迟的不确定性（Noisy Neighbor）
- 云存储的最终一致性与应用预期冲突
- 多租户环境下的安全和隔离

## 7. 工程实践

- 在 AWS/GCP 上部署一个自动伸缩的 Web 服务
- 使用 Terraform 或 Pulumi 管理云基础设施即代码
- 设计考虑区域故障的高可用架构（多 AZ、多 Region）
- 使用托管服务（如 RDS、S3）降低运维复杂度

## 8. 与其他主题的关系

| 相关主题 | 关系 |
|----------|------|
| 分布式系统 | 云是最大的分布式系统 |
| 操作系统 | 虚拟化和容器依赖 OS 内核机制 |
| 数据库 | 云数据库（如 Aurora、Spanner）是分布式数据库的产业实践 |
| 网络安全 | 云安全、IAM、网络策略 |
