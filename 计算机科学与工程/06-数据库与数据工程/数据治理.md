# 数据治理

## 1. 一句话定义

数据治理是确保数据的可用性、质量、安全性和合规性的组织框架和技术实践，覆盖数据从产生到归档的全生命周期。

## 2. 核心问题

- 如何确保数据是可信的（准确、完整、一致）？
- 如何追踪数据的来源和变换过程（血缘）？
- 如何在不阻碍业务的前提下保护数据和遵守法规？

## 3. 知识框架

| 维度 | 核心内容 | 关键技术/实践 |
|------|----------|---------------|
| 数据质量 | 准确性、完整性、一致性、及时性 | 数据校验、质量监控 |
| 元数据管理 | 业务元数据、技术元数据、操作元数据 | 数据目录（DataHub）|
| 数据血缘 | 端到端的数据流转和变换追踪 | 自动血缘采集 |
| 数据安全与合规 | 访问控制、分类分级、GDPR | RBAC、数据脱敏 |
| 数据生命周期 | 归档、删除、冷热分离 | 数据保留策略 |

## 4. 关键概念

- **数据目录（Data Catalog）**：可搜索的数据资产清单，回答"我们有什么数据、在哪里、谁负责"
- **数据血缘（Data Lineage）**：追踪数据从源表经过哪些 ETL 变换到达目标表
- **主数据管理（MDM）**：确保核心业务实体（客户、产品）在所有系统中有一致定义
- **数据网格（Data Mesh）**：去中心化的数据所有权——由领域团队负责自己数据的质量和服务化
- **数据契约（Data Contract）**：上下游之间对数据 Schema 和质量标准的约定

## 5. 典型实践

### 5.1 数据质量六维度

| 维度 | 衡量什么 |
|------|----------|
| 准确性 | 数据是否反映真实情况 |
| 完整性 | 必要字段是否缺失 |
| 一致性 | 跨系统/表的相同数据是否一致 |
| 及时性 | 数据是否在需要时可用 |
| 唯一性 | 是否存在重复记录 |
| 有效性 | 数据是否符合定义的格式和规则 |

### 5.2 数据治理技术栈

```
采集层：元数据采集器（爬取 DB schema、ETL 日志）
     ↓
存储层：元数据存储（图数据库 / 关系库）
     ↓
服务层：数据目录、血缘查询、质量监控
     ↓
应用层：数据发现、合规审计、影响分析
```

## 6. 经典问题

- 数据治理的"过度设计"导致数据团队成为瓶颈
- 业务元数据和技术元数据的断层
- 同名异物和同物异名的困扰
- GDPR/个人信息保护法的合规代价

## 7. 工程实践

- 为项目建立简单的数据文档（字段说明、数据来源）
- 使用 Great Expectations 或 dbt tests 实现自动数据质量检查
- 搭建简单的数据目录（如用 Amundsen 或 DataHub）
- 实现基本的 PII 检测和脱敏规则

## 8. 与其他主题的关系

| 相关主题 | 关系 |
|----------|------|
| 数据仓库 | 数仓的维度建模和 ETL 依赖治理保证质量 |
| 大数据系统 | 数据血缘需追踪批处理和流处理 Pipeline |
| 软件工程 | 数据契约是 API 契约的数据版 |
| 网络安全 | 数据分类分级和访问控制 |
