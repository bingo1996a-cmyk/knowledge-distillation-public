# 大数据系统

## 1. 一句话定义

大数据系统处理传统单机数据库无法承载的超大规模数据集，通过分布式批处理和流处理框架实现数据的存储、计算和分析。

## 2. 核心问题

- 如何并行处理 PB 级别的数据？
- 如何在数据产生的瞬间就进行分析？
- 如何保证大规模数据处理中的容错性？

## 3. 知识框架

| 范式 | 处理模式 | 代表性系统 |
|------|----------|------------|
| 批处理 | 先存储，再批量计算 | Hadoop MapReduce、Spark |
| 流处理 | 数据到达即处理 | Flink、Kafka Streams |
| 湖仓一体 | 数据湖 + 数仓特性 | Delta Lake、Iceberg + Spark |

## 4. 关键概念

- **MapReduce 范式**：Map（映射，局部计算）→ Shuffle（重分布）→ Reduce（聚合）——批处理的理论原型
- **数据局部性**：将计算移动到数据所在节点，减少网络传输
- **弹性分布式数据集（RDD）**：Spark 的核心抽象——不可变、可容错的分布式数据集合
- **事件时间 vs 处理时间**：流处理的核心时间语义区分
- **精确一次语义（Exactly-Once）**：最难实现的流处理保证——每条记录恰好被处理一次

## 5. 典型系统

### 5.1 Apache Spark 架构

```
Driver（协调）→ Cluster Manager（资源分配）
                      ↓
                Executor（执行 + 存储）
                      ↓
                  HDFS / S3 / ...
```

核心：基于内存的 RDD 计算，避免 MapReduce 的频繁磁盘 I/O。

### 5.2 批处理 vs 流处理

| 维度 | 批处理（Spark）| 流处理（Flink）|
|------|---------------|---------------|
| 延迟 | 分钟级 | 毫秒-秒级 |
| 数据 | 有界数据集 | 无界数据流 |
| 正确性 | 幂等重跑 | 状态管理 + 检查点 |
| 典型场景 | 日报、模型训练 | 实时风控、监控告警 |

## 6. 经典问题

- 数据倾斜——个别 Partition 过大导致长尾任务
- 小文件问题——大量小文件对 HDFS/对象存储的性能冲击
- 反压（Backpressure）——下游消费慢导致上游堆积
- 检查点开销——流处理的状态快照代价

## 7. 工程实践

- 用 PySpark 对大规模日志进行 ETL 和聚合分析
- 用 Flink 或 Kafka Streams 实现实时数据处理 Pipeline
- 理解 Spark Shuffle 过程，学习如何通过分区优化减少 Shuffle
- 对比批处理和流处理在同一数据集上的延迟差异

## 8. 与其他主题的关系

| 相关主题 | 关系 |
|----------|------|
| 分布式系统 | 大数据引擎是最经典的分布式系统应用 |
| 数据库 | 数仓建设依赖批处理 ETL，实时数仓依赖流处理 |
| 云计算 | 对象存储（S3）和弹性计算使大数据系统可伸缩 |
| 机器学习 | 分布式训练和特征工程依赖大数据平台 |
