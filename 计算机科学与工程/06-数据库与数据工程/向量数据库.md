# 向量数据库

## 1. 一句话定义

向量数据库（Vector Database）专门存储和检索高维向量嵌入，通过近似最近邻（ANN）算法实现毫秒级的相似性搜索，是 RAG（检索增强生成）和语义搜索的核心基础设施。

## 2. 核心问题

- 如何在数百万甚至数十亿的高维向量中快速找到最相似的 K 个？
- 如何在精度、速度和资源占用之间权衡？
- 如何与传统结构化数据和全文搜索结合？

## 3. 知识框架

| 主题 | 核心内容 |
|------|----------|
| 向量嵌入 | 文本/图像→向量的转换（Embedding Model）|
| 相似度度量 | 余弦相似度、欧氏距离、内积 |
| ANN 索引 | 近似最近邻搜索算法 |
| 过滤搜索 | 在 ANN 搜索基础上叠加元数据过滤 |
| 混合搜索 | 向量相似度 + 关键词匹配的组合 |

## 4. 关键概念

- **向量嵌入（Embedding）**：将非结构化数据（文本、图像）映射为固定维度的实数向量——语义相似的输入距离相近
- **ANN vs KNN**：精确 KNN（O(n×d) 不可扩展）→ 近似 ANN（牺牲微小精度换取 10-1000× 速度提升）
- **HNSW（层级可导航小世界图）**：当前最流行的 ANN 索引算法——构建多层图，搜索时贪心地向更近节点移动
- **IVF（倒排文件索引）**：将向量空间聚类为多个质心区域，搜索时只查看最相关的几个区域
- **量化（Quantization）**：将向量压缩为更小的表示（如 PQ——乘积量化），牺牲部分精度换取内存和带宽节省

## 5. 典型方法

### 5.1 ANN 算法对比

| 算法 | 索引构建 | 查询速度 | 内存占用 | 精度 |
|------|----------|----------|----------|------|
| HNSW | 慢 | 极快 | 高 | 极高 |
| IVF+PQ | 快 | 快 | 低 | 中高 |
| DiskANN | 慢 | 快 | 极低(SSD) | 高 |
| LSH | 快 | 中 | 中 | 低 |

### 5.2 主流向量数据库

| 系统 | 特点 |
|------|------|
| Milvus | 开源，云原生架构，功能全面 |
| Pinecone | 托管服务，零运维 |
| Qdrant | Rust 编写，高性能 |
| Weaviate | 原生支持混合搜索（向量+关键词）|
| pgvector | PostgreSQL 扩展，与关系数据共存 |

## 6. 经典问题

- 精度 vs 速度——ANN 的本质权衡，不同场景对召回率要求不同
- 索引构建时间——HNSW 构建慢，适合静态或准静态数据集
- 混合搜索——metadata filter + vector similarity 的工程挑战
- Embedding 模型的选型和更新——模型升级后旧向量需要重新编码

## 7. 工程实践

- 用 pgvector 在 PostgreSQL 上实现简单的语义搜索
- 用 Milvus/Qdrant 搭建 RAG 系统的向量检索层
- 对比不同 Embedding 模型（OpenAI/text-embedding、BGE、E5）的检索效果
- 实现混合搜索——向量相似度 + 元数据过滤
