# 分布式数据库

## 1. 一句话定义

分布式数据库将数据存储在多个物理节点上，通过复制保证可用性、分片实现扩展，并在此之上提供一致的数据视图。

## 2. 核心问题

- 如何在多节点故障时保持数据不丢失、服务不中断？
- 如何将数据分散到多个节点同时保持查询能力？
- 如何在大规模分布式中实现事务的 ACID 特性？

## 3. 知识框架

| 技术 | 解决什么 | 典型实现 |
|------|----------|----------|
| 复制（Replication）| 数据高可用、读扩展 | 主从、多主、无主 |
| 分片（Sharding）| 数据水平扩展 | 哈希分片、范围分片 |
| 分布式事务 | 跨节点原子操作 | 2PC、Percolator |
| 共识 | 选主、配置元数据一致性 | Raft（etcd、TiKV）|
| 分布式查询 | 跨节点查询优化 | 查询下推、并行执行 |

## 4. 关键概念

- **复制模式**：主从（简单，写走主）、多主（写任意，需冲突解决）、无主（Quorum 读写，如 Dynamo）
- **主从切换**：手动 vs 自动（Raft 选主），自动切换需解决脑裂
- **分片策略**：哈希分片（均匀分布，范围查询困难）、范围分片（支持范围查询，可能热点）
- **NewSQL**：兼具关系数据库的 SQL/ACID 和 NoSQL 的水平扩展能力（如 CockroachDB、TiDB）
- **HTAP**：混合事务/分析处理，在同一系统内同时支持 OLTP 和 OLAP

## 5. 典型系统

### 5.1 Google Spanner 架构思路

```
TrueTime API（高精度时钟）→ 外部一致性
 + 分片 + Paxos 复制组 + 2PC
 → 全球分布且外部一致的关系数据库
```

### 5.2 主流分布式数据库分类

| 类型 | 代表系统 | 关键特性 |
|------|----------|----------|
| NewSQL | CockroachDB、TiDB | SQL + 水平扩展 + 分布式事务 |
| 文档型 | MongoDB | 灵活 Schema + 复制集 + 自动分片 |
| 宽列 | Cassandra | 无主架构 + 最终一致性 + 高写入吞吐 |
| KV 存储 | etcd、TiKV | 强一致 + Raft + 简单接口 |

## 6. 经典问题

- 分布式事务的锁竞争和延迟放大
- 全局二级索引的维护开销
- 数据再平衡（Rebalance）对在线服务的影响
- 大分片的热点问题

## 7. 工程实践

- 搭建简单的 MySQL 主从复制实验
- 使用 etcd 理解基于 Raft 的强一致 KV 存储
- 在应用层实现基于一致性哈希的分片逻辑
- 对比单机 PostgreSQL 和分布式 CockroachDB 在简单场景下的延迟差异

## 8. 与其他主题的关系

| 相关主题 | 关系 |
|----------|------|
| 分布式系统 | 共识、复制、CAP 定理是分布式数据库的理论基础 |
| 关系数据库 | 分布式 SQL 数据库继承并扩展了关系模型 |
| 云计算 | 云原生数据库（如 Aurora）在云上实现 |
