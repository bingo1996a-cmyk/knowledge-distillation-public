# 无锁编程

## 1. 一句话定义

无锁编程（Lock-Free Programming）使用原子操作和内存序而非互斥锁来协调并发访问，避免锁带来的死锁、优先级反转和上下文切换开销——在高性能系统的热路径中至关重要。

## 2. 核心问题

- 如何在不用锁的情况下安全地并发操作共享数据？
- CPU 内存模型的乱序执行如何影响并发正确性？
- 无锁一定比有锁快吗？

## 3. 知识框架

| 主题 | 核心内容 |
|------|----------|
| 原子操作 | CAS（Compare-And-Swap）、FAA（Fetch-And-Add）|
| 内存序 | 顺序一致性、获取-释放、松弛 |
| 进展保证 | 无等待、无锁、无阻碍 |
| 无锁数据结构 | 无锁栈、队列、哈希表 |
| 内存回收 | RCU、Hazard Pointer、Epoch-Based |

## 4. 关键概念

- **CAS（Compare-And-Swap）**：`CAS(&var, old, new)`——如果 var==old，原子地将 var 设为 new 并返回 true——无锁编程的"万能原语"
- **ABA 问题**：CAS 检查值从 A 变到 B 又变回 A 时误判为未改变——解决方案：标记指针（Tagged Pointer）添加版本号
- **内存序（Memory Order）**：
  - Relaxed：无顺序保证，仅原子性
  - Acquire-Release：获取后可见释放前的写入
  - Sequentially Consistent：全局一致的顺序（最直观但最贵）
- **进度保证**：无等待（每个操作有限步完成）> 无锁（某线程有限步完成）> 无阻碍（仅在无竞争时保证）
- **RCU（Read-Copy-Update）**：读者无开销（直接读），写者创建新版本+等待所有读者离开旧版本后回收——Linux 内核广泛使用

## 5. 典型方法

### 5.1 无锁栈（Treiber Stack）

```
push(node):
  do:
    node->next = top.load()
  while !CAS(&top, node->next, node)

pop():
  do:
    node = top.load()
    if node == null: return EMPTY
    next = node->next
  while !CAS(&top, node, next)
  return node->value
```

### 5.2 锁 vs 无锁

| 维度 | 互斥锁 | 无锁 |
|------|--------|------|
| 阻塞 | 持有锁期间阻塞其他线程 | 不阻塞 |
| 死锁风险 | 有 | 无 |
| 优先级反转 | 有 | 无 |
| 低竞争性能 | 好 | 好 |
| 高竞争性能 | 退化严重 | 退化较轻 |
| 正确性 | 相对易 | 极难 |

## 6. 经典问题

- x86 vs ARM 内存模型差异——x86 强内存模型（TSO，很多隐式保证），ARM 弱内存模型（需显式内存屏障）
- 伪共享——两个不相关的原子变量在同一缓存行导致缓存颠簸
- 无锁队列的工程实现——Michael-Scott 队列
- RCU 的宽限期——读者离开临界区后才可回收旧数据
