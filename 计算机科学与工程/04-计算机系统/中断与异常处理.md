# 中断与异常处理

## 1. 一句话定义

中断和异常是 CPU 响应异步事件（硬件信号）和同步事件（程序错误/系统调用）的核心机制，是操作系统实现多任务、设备管理和安全隔离的硬件基础。

## 2. 核心问题

- CPU 如何从正常的指令执行流"跳出"来处理突发事件？
- 中断和异常在硬件层面如何区分和处理？
- 为什么中断处理要分上半部和下半部？

## 3. 知识框架

| 机制 | 触发来源 | 同步/异步 | 示例 |
|------|----------|-----------|------|
| 硬件中断 | 外部设备 | 异步 | 网卡收包、定时器滴答 |
| 异常（Fault）| 指令执行 | 同步 | 缺页、除零 |
| 陷阱（Trap）| 指令执行 | 同步 | 系统调用、断点 |
| 软件中断 | 程序主动触发 | 同步 | int 指令（x86）、syscall |

## 4. 关键概念

- **中断向量表（IVT/IDT）**：存放每种中断/异常的处理函数入口地址——CPU 根据中断向量号查表跳转（x86-64 用 IDT——中断描述符表，每个条目 16 字节，最多 256 个）
- **中断上下文**：中断处理程序运行在独立于任何进程的执行上下文中——不能睡眠、不能调用可能阻塞的函数
- **上半部 vs 下半部**：上半部（硬中断上下文，极短时间完成——应答硬件、调度下半部）vs 下半部（软中断/tasklet/工作队列，完成耗时操作——如 TCP 协议栈处理）
- **中断禁用**：关键临界区通过禁用本地中断（local_irq_disable）保护——必须极短，否则丢中断
- **APIC（高级可编程中断控制器）**：多核系统中的中断路由——IO-APIC 接收外部中断，Local APIC 分配给各 CPU 核

## 5. 典型机制

### 5.1 中断处理流程（x86-64）

```
硬件触发中断
  → APIC 路由到目标 CPU
  → CPU 完成当前指令
  → 保存关键上下文（RIP/CS/RFLAGS/RSP/SS）
  → 从 IDT 中查询中断向量号对应的处理函数
  → 切换到内核栈 → 执行中断处理程序
  → iret 指令恢复上下文 → 回到中断前的执行流
```

### 5.2 异常类型

| 异常号 | 名称 | 原因 |
|--------|------|------|
| #DE (0) | 除零 | div/idiv 除数为 0 |
| #PF (14) | 缺页 | 虚拟地址未映射/无权限 |
| #GP (13) | 一般保护 | 访问非法段/特权级违规 |
| #UD (6) | 非法指令 | 执行未定义的操作码 |
| #MC (18) | 机器检查 | 硬件错误 |

## 6. 经典问题

- 中断延迟——从硬件触发中断到执行处理程序第一条指令的时间
- 中断风暴——设备不断触发中断导致 CPU 被淹没（关闭中断→轮询切换）
- 优先级反转——低优先级中断被高优先级中断阻塞太久
- NMI（Non-Maskable Interrupt）——不可屏蔽中断用于最关键的硬件故障

## 7. 工程实践

- 查看 `/proc/interrupts` 观察系统的中断分布
- 用 `perf top` 观察中断和软中断的 CPU 占用
- 用 `irqbalance` 在多个 CPU 间均衡硬件中断
- 理解网卡中断亲和性（IRQ Affinity）如何影响网络性能
