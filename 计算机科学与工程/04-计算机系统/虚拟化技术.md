# 虚拟化技术

## 1. 一句话定义

虚拟化技术在物理硬件之上创建抽象层，使多个操作系统或应用实例可以共享同一硬件资源，同时保持隔离——是云计算的核心使能技术。

## 2. 核心问题

- 如何让多个 OS 安全、高效地共享同一 CPU？
- 虚拟机、容器、unikernel 各自的适用场景是什么？
- 虚拟化开销有多大？如何测量和降低？

## 3. 知识框架

| 虚拟化层次 | 核心内容 | 代表性技术 |
|------------|----------|------------|
| CPU 虚拟化 | 特权指令截获与模拟 | VT-x/AMD-V、二进制翻译 |
| 内存虚拟化 | 客户物理→宿主机物理映射 | EPT/NPT 二级页表 |
| I/O 虚拟化 | 设备模拟与直通 | virtio、SR-IOV、VDUSE |
| OS 级虚拟化 | 内核命名空间隔离 | Linux namespace/cgroup（Docker）|

## 4. 关键概念

- **Hypervisor（虚拟机监视器）**：Type 1（裸金属，如 KVM、ESXi）直接运行在硬件上；Type 2（如 VirtualBox）运行在宿主 OS 上
- **全虚拟化 vs 半虚拟化**：全虚拟化（Guest OS 无需修改，使用硬件辅助）vs 半虚拟化（Guest OS 需修改以使用 hypercall 接口，性能更好但需改动）
- **虚拟机 vs 容器**：VM 虚拟化硬件（强隔离，每个 VM 有独立内核），容器虚拟化 OS（轻量，共享内核）
- **EPT（扩展页表）**：Intel 的二级地址转换——Guest VA→Guest PA→Host PA，硬件完成，极低开销
- **实时迁移（Live Migration）**：在 VM 运行期间将其从一台物理机迁移到另一台，对服务影响极小

## 5. 典型机制

### 5.1 Popek-Goldberg 虚拟化条件

```
可虚拟化的 ISA 必须满足：
1. 所有敏感指令（影响系统状态）都是特权指令
2. 执行敏感指令时能触发 trap

x86 在 VT-x 之前不满足条件（部分敏感指令在用户态静默执行）
→ 通过二进制翻译（VMware）或硬件辅助（Intel VT-x/AMD-V）解决
```

### 5.2 VM vs 容器 vs Unikernel

| 方案 | 隔离级别 | 启动 | 密度 | 适用场景 |
|------|----------|------|------|----------|
| VM | 硬件级 | 秒-分钟 | 数十 | 多租户云、安全优先 |
| 容器 | OS 级 | 毫秒-秒 | 数百 | 微服务、CI/CD |
| Unikernel | 应用级 | 毫秒 | 极高 | 专用微服务 |

## 6. 经典问题

- CPU 虚拟化开销——VM Exit（Guest 切换到 Host）的代价
- 内存过量分配（Memory Overcommit）导致的 Ballooning 和交换
- 网络虚拟化的性能损耗——从 virtio 到 SR-IOV 再到 DPU
- 容器逃逸——攻击者突破 namespace 隔离获取宿主机权限

## 8. 与其他主题的关系

| 相关主题 | 关系 |
|----------|------|
| 操作系统 | namespace/cgroup 是 OS 级虚拟化的基础 |
| 云计算 | IaaS 层依赖虚拟机，PaaS 层依赖容器 |
| 容器技术 | 容器是 OS 级虚拟化的产业级应用 |
| 安全 | 虚拟机隔离是云安全的基础 |
