# 内存管理详解

## 1. 一句话定义

操作系统内存管理通过虚拟内存为每个进程创造独立、连续的地址空间幻觉，底层通过分页、页表和页面置换将虚拟地址映射到物理内存和磁盘。

## 2. 核心问题

- 每个进程的 4GB/256TB 地址空间从哪来？
- 物理内存不够时系统如何应对？
- 为什么有时系统内存很空却很慢？

## 3. 知识框架

| 主题 | 核心机制 | 关键概念 |
|------|----------|----------|
| 地址空间 | 虚拟地址→物理地址映射 | 页表、TLB |
| 分页 | 固定大小页帧管理 | 页表条目（PTE）、多级页表 |
| 页面置换 | 物理内存不够时选哪页换出 | LRU、Clock、工作集 |
| 内核内存 | 内核如何管理自己的内存 | 伙伴系统、slab 分配器 |
| 高级特性 | 大页、内存去重 | THP、KSM、HugeTLB |

## 4. 关键概念

- **虚拟内存三功能**：隔离（进程之间互不可见）、抽象（不关心物理地址）、扩展（利用磁盘扩展可用内存）
- **页表（Page Table）**：将虚拟页号（VPN）映射到物理帧号（PFN）的数据结构——x86-64 用四级页表（PGD→PUD→PMD→PTE），每级 9 位索引
- **TLB（Translation Lookaside Buffer）**：页表条目的 CPU 片上缓存——TLB Miss 的成本高达数十个时钟周期
- **页面错误（Page Fault）**：访问未映射或不在物理内存中的地址——分为 Minor Fault（已分配但未映射）和 Major Fault（需从磁盘换入）
- **工作集（Working Set）**：进程在某个时间段内需要访问的页面集合——WS > 可用物理内存 → 抖动

## 5. 典型机制

### 5.1 x86-64 四级页表地址转换

```
虚拟地址（48 位）：
| 9 bits PGD | 9 bits PUD | 9 bits PMD | 9 bits PTE | 12 bits Offset |

1. CR3 寄存器 → PGD 基地址
2. PGD[PGD_idx] → PUD 基地址
3. PUD[PUD_idx] → PMD 基地址
4. PMD[PMD_idx] → PTE 基地址
5. PTE[PTE_idx] → 物理帧号（PFN）
6. PFN + Offset → 最终物理地址
```

### 5.2 伙伴系统（Buddy System）

```
Linux 内核分配物理页的核心算法：
- 维护 11 个自由链表（阶 0-10：1页、2页、4页...1024页）
- 分配：找到足够大的块 → 必要时递归分裂
- 释放：释放块 → 检查"伙伴"是否空闲 → 合并后继续向上合并
目的：减少外部碎片
```

## 6. 经典问题

- TLB Shootdown——多核修改页表时需使其他核的 TLB 失效（IPI 开销）
- 页面抖动——内存过载时系统花费 90%+ 时间在换页上
- 内存碎片——外部碎片（无连续大块）和内部碎片（分配块内浪费）
- 缺页中断的延迟——从磁盘换入一页需要 ~10ms

## 7. 工程实践

- 查看 `/proc/<pid>/maps` 理解进程的虚拟地址空间布局
- 用 `vmstat` 观察系统的页面换入/换出活动
- 用 `perf stat -e page-faults` 统计缺页
- 配置 Huge Pages 测试大页对 TLB 命中率的影响
