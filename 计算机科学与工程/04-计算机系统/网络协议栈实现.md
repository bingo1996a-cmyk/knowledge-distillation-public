# 网络协议栈实现

## 1. 一句话定义

操作系统中的网络协议栈实现了从网卡中断到 Socket 接口的完整数据路径，是理解网络性能、调优和调试的底层基础。

## 2. 核心问题

- 一个网络包从网卡到应用程序经历了哪些步骤？
- 内核如何使用软中断和 NAPI 处理高吞吐网络？
- 数据拷贝次数如何影响网络性能？

## 3. 知识框架

| 层次 | 核心内容 | 关键数据结构 |
|------|----------|--------------|
| 网卡驱动 | 中断处理、DMA、环形缓冲区 | 描述符环 |
| NAPI/软中断 | 轮询收包、减少中断 | softirq、NAPI |
| 网络层（IP）| 路由查找、分片重组、Netfilter | 路由表、连接跟踪 |
| 传输层（TCP/UDP）| 连接管理、状态机、拥塞控制 | Socket 缓冲区、TCB |
| Socket 层 | 文件描述符接口 | `struct socket`、VFS 集成 |

## 4. 关键概念

- **sk_buff（Socket Buffer）**：Linux 内核中网络数据包的核心数据结构——包含数据指针、协议头指针、网络设备和元数据——整个协议栈中传递的就是这个结构
- **NAPI（New API）**：中断 + 轮询混合——第一个包到达触发硬中断 → 关闭中断 → 软中断轮询收包直到队列空——减少中断开销
- **零拷贝（Zero Copy）**：数据从网卡 DMA 到内核缓冲区 → 通过 `sendfile`/`splice` 直接发送到另一 Socket——不经过用户空间
- **Netfilter/iptables**：Linux 内核包过滤框架——5 个钩子点（Prerouting、Input、Forward、Output、Postrouting）——防火墙、NAT 的基础
- **eBPF/XDP**：在网卡驱动层直接运行沙箱化的程序——旁路内核栈，可达线速处理（用于 DDoS 防御、负载均衡）

## 5. 典型机制

### 5.1 收包路径（简要）

```
1. 网卡收到帧 → DMA 写入环形缓冲区
2. 网卡触发硬中断 → CPU 运行 ISR
3. ISR 调度 NAPI 软中断（NET_RX_SOFTIRQ）
4. 软中断调用驱动 poll() 从环中取包
5. sk_buff 沿协议栈向上：
   驱动 → 以太网层 → IP 层（路由、Netfilter）→ TCP 层
6. TCP 处理：查连接、验证序列号、放入接收队列
7. 数据就绪 → 唤醒等待的应用程序（epoll/select）
```

### 5.2 数据拷贝次数

```
传统路径（4 次拷贝）：
  网卡 DMA → 内核 sk_buff
  kernel → user（read 拷贝）
  user → kernel（write 拷贝）
  kernel → 网卡 DMA（发送）

sendfile 零拷贝（2 次拷贝）：
  网卡 DMA → 内核页缓存
  内核页缓存 → 网卡 DMA（直接）
```

## 6. 经典问题

- 中断风暴——高吞吐时每个包触发一个中断导致 CPU 被中断淹没
- SoftIRQ 占用过高导致用户空间饥饿
- 接收队列溢出——应用程序消费速度小于收包速度
- TCP incast 问题——多对一通信导致交换机缓冲区溢出

## 7. 工程实践

- 使用 `ethtool` 调整网卡环形缓冲区大小和中断合并参数
- 用 `dropwatch` 和 `/proc/net/softnet_stat` 诊断丢包位置
- 用 `ss -s` 查看 TCP 统计和 socket 内存使用
- 用 eBPF 程序追踪网络包在协议栈中的路径
