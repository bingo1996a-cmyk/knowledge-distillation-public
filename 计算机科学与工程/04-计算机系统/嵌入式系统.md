# 嵌入式系统

## 1. 一句话定义

嵌入式系统是专用于特定功能的计算系统，通常受限于功耗、体积、实时性和成本，广泛存在于物联网设备、汽车电子、医疗设备和工业控制中。

## 2. 核心问题

- 如何在极有限的资源（内存、算力、电量）下完成指定任务？
- 如何保证系统在规定时间内做出确定性响应？
- 硬件和软件如何协同设计以最小化开销？

## 3. 知识框架

| 子领域 | 核心内容 | 关键技术 |
|--------|----------|----------|
| 微控制器（MCU）| ARM Cortex-M、外设、中断 | 裸机编程、HAL |
| 实时操作系统 | 确定性调度、优先级管理 | FreeRTOS、Zephyr |
| 硬件-软件协同 | 外设驱动、内存映射 | Device Tree、DMA |
| 低功耗设计 | 休眠模式、动态调频 | 功耗状态管理 |
| 物联网连接 | BLE、Wi-Fi、LoRa | MQTT、CoAP |

## 4. 关键概念

- **实时性**：硬实时（错过截止 = 系统失效）vs 软实时（错过截止 = 服务质量下降）
- **中断与中断服务程序（ISR）**：硬件事件异步触发，ISR 必须在极短时间内完成
- **内存映射 I/O（MMIO）**：外设寄存器映射到内存地址空间，通过读写内存操作硬件
- **看门狗定时器（Watchdog）**：系统卡死时自动复位的关键安全机制
- **交叉编译**：在宿主平台（x86）编译出目标平台（ARM/RISC-V）代码

## 5. 典型机制

### 5.1 嵌入式 Linux vs 裸机/RTOS

| 方案 | 适用场景 | 开销 | 实时性 |
|------|----------|------|--------|
| 裸机（Bare Metal）| 极简系统、低功耗传感器 | 最小 | 软件保证 |
| RTOS（FreeRTOS）| 需要多任务但有实时约束 | 小（~10KB）| 确定性调度 |
| 嵌入式 Linux | 复杂应用、网络功能 | 大（~MB 内存）| 软实时（需 PREEMPT_RT）|

### 5.2 中断处理流程

```
硬件触发中断 → CPU 保存上下文 → 查中断向量表 → 跳转 ISR
→ ISR 快速处理关键逻辑 → 设置标志位/发送信号量 → 返回
→ 后台任务处理非紧急部分（下半部/Bottom Half）
```
