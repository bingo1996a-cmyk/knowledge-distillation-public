# AI 对齐与安全

## 1. 一句话定义

AI 对齐（Alignment）研究如何确保 AI 系统的行为与人类意图和价值观一致，AI 安全研究如何防止 AI 系统造成意外伤害——二者是 AI 大规模部署的前提。

## 2. 核心问题

- 如何让模型理解并遵循人类意图而非字面指令？
- 如何检测和防止模型的有害输出？
- 随着模型能力增强，如何确保其始终保持安全？

## 3. 知识框架

| 方向 | 核心问题 | 代表性方法 |
|------|----------|------------|
| 偏好对齐 | 让模型输出符合人类偏好 | RLHF、DPO、KTO |
| 安全过滤 | 检测和阻止有害内容 | 内容过滤器、输入/输出护栏 |
| 红队测试 | 主动发现模型漏洞 | 对抗性提示、越狱测试 |
| 可解释性 | 理解模型为什么这样决策 | 机制解释性、探测分类器 |
| 鲁棒性 | 模型在分布外和对抗输入下的可靠性 | 对抗训练、安全提示 |

## 4. 关键概念

- **RLHF（人类反馈强化学习）**：用人类偏好作为奖励信号训练模型——InstructGPT/ChatGPT 的对齐方法
- **DPO（直接偏好优化）**：绕过显式奖励模型，直接从偏好数据优化策略——更简单更稳定
- **奖励黑客（Reward Hacking）**：模型找到最大化奖励但并非真正有益的捷径
- **红队测试**：用有组织的对抗性测试发现模型的安全漏洞——类似安全领域渗透测试
- **宪法式 AI（Constitutional AI）**：让模型根据预定义的"宪法"（行为准则）自我批评和改进

## 5. 典型方法

### 5.1 RLHF 流程

```
1. 收集人类对模型输出的偏好数据
2. 训练奖励模型（RM）预测人类偏好
3. 用 PPO 强化学习优化模型，使 RM 评分最大
4. 加上 KL 惩罚防止模型偏离原始行为太远
```

### 5.2 主要对齐方法对比

| 方法 | 需要奖励模型 | 需要在线采样 | 复杂度 | 稳定性 |
|------|-------------|-------------|--------|--------|
| RLHF (PPO) | 是 | 是 | 高 | 中 |
| DPO | 否 | 否 | 中 | 高 |
| KTO | 否 | 否 | 低 | 高 |
| Constitutional AI | 部分 | 部分 | 高 | 中 |

## 6. 经典问题

- 对齐税——安全训练可能降低模型在某些任务上的能力
- 过度拒绝——模型将无害输入误判为有害而拒绝回答
- 多语言安全——安全训练在不同语言间的效果不均衡
- 越狱（Jailbreak）——通过精巧的提示工程突破安全限制
- 模型输出安全评估的自动化

## 7. 工程实践

- 用 RLHF/DPO 微调开源模型改善安全行为
- 实现基本的内容安全过滤器
- 对自有模型进行红队测试
- 理解 Claude/OpenAI 等模型的安全报告和评估方法
