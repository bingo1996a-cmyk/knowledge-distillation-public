# 知识图谱

## 1. 一句话定义

知识图谱（Knowledge Graph）用结构化三元组（实体-关系-实体）组织知识，将信息从孤立的文档转化为可推理、可查询、可扩展的互联知识网络。

## 2. 核心问题

- 如何从非结构化文本中抽取实体和关系？
- 如何统一融合来自不同来源的知识？
- 如何在图谱上进行推理——从已知事实推断新事实？

## 3. 知识框架

| 层次 | 核心内容 | 关键技术 |
|------|----------|----------|
| 知识表示 | 本体论、RDF、OWL | 三元组、描述逻辑 |
| 知识抽取 | NER、关系抽取、事件抽取 | 预训练模型+微调、少样本 |
| 知识融合 | 实体对齐、实体链接 | 嵌入匹配、规则匹配 |
| 知识推理 | 逻辑推理、路径推理 | 规则推理、嵌入推理 |
| 存储与查询 | 图存储、SPARQL | Neo4j、Virtuoso |

## 4. 关键概念

- **三元组（Triple）**：(头实体, 关系, 尾实体)——如 (北京, 是首都, 中国)——知识图谱的基本原子单元
- **本体论（Ontology）**：定义领域内的概念类别、属性和关系——Schema 层——如"人"是"生物"的子类、"国籍"是"人"的属性
- **RDF/OWL**：RDF（资源描述框架）是 W3C 的图数据交换标准；OWL（Web 本体语言）在 RDF 上增加逻辑表达能力
- **知识嵌入（Knowledge Embedding）**：将实体和关系映射到低维向量空间——TransE: h+r≈t——头实体向量+关系向量≈尾实体向量
- **链接预测**：预测缺失的三元组——(实体, ?, 实体) 或 (?, 关系, ?)——知识图谱补全的核心任务

## 5. 典型方法

### 5.1 知识图谱构建流程

```
非结构化文本（Wikipedia、论文、新闻）
    ↓
命名实体识别（NER）→ 抽取人/地/组织/...
    ↓
关系抽取（RE）→ (实体, 关系, 实体)
    ↓
实体链接（EL）→ 将文本提及链接到 KG 中的实体
    ↓
知识融合 → 合并来自多个来源的等价实体
    ↓
知识图谱
```

### 5.2 知名知识图谱

| 图谱 | 领域 | 规模 |
|------|------|------|
| Wikidata | 通用 | >1 亿实体 |
| DBpedia | 从 Wikipedia 抽取 | 数百万实体 |
| Google Knowledge Graph | 通用 | 数十亿三元组 |
| UMLS | 医学生物 | 数百万概念 |

## 6. 经典问题

- 实体歧义——"苹果"是公司还是水果
- 知识冲突——不同来源对同一事实的矛盾
- 知识完备性——知识图谱永远不完整
- 推理的可扩展性——规则推理在大规模 KGs 上效率低

## 7. 工程实践

- 用 Wikidata 的 SPARQL 接口查询结构化知识
- 用 spaCy 或 Stanza 进行实体和关系抽取
- 用 PyKEEN 训练知识嵌入模型（TransE、RotatE）
- 用 Neo4j 构建并查询领域知识图谱
