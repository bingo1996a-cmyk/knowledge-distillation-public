# 零知识证明

## 1. 一句话定义

零知识证明（Zero-Knowledge Proof, ZKP）允许证明者向验证者证明"我知道某个秘密"或"某个陈述为真"，而不泄露关于秘密本身的任何信息，是隐私保护和区块链可扩展性的关键技术。

## 2. 核心问题

- 如何证明"我知道答案"而不泄露答案本身？
- 如何让证明足够短小，以便在区块链上高效验证？
- 如何在通用计算中应用零知识证明？

## 3. 知识框架

| 类型 | 核心特点 | 代表性方案 |
|------|----------|------------|
| ZK-SNARK | 证明小、验证快、需可信设置 | Groth16 |
| ZK-STARK | 无需可信设置、抗量子、证明较大 | StarkWare |
| 交互式 ZKP | 多轮交互完成证明 | Sigma 协议 |
| 非交互式 ZKP | 单次发送证明 | Fiat-Shamir 变换 |
| 递归 ZKP | 一个证明验证另一个证明 | Plonky2、Nova |

## 4. 关键概念

- **完备性（Completeness）**：如果陈述为真，诚实的证明者可以说服验证者
- **可靠性（Soundness）**：如果陈述为假，作弊的证明者无法说服验证者（除非概率可忽略）
- **零知识性（Zero-Knowledge）**：验证者除了"陈述为真"外什么也没学到
- **可信设置（Trusted Setup）**：一次性生成公共参数，过程中产生的"有害废料"必须销毁——若保留可伪造证明
- **算术电路**：将待证明的计算转化为加法和乘法门组成的电路——ZKP 系统的输入格式

## 5. 典型机制

### 5.1 洞穴类比（零知识的思想实验）

```
证明者(Peggy)知道洞穴中连接A入口和B入口的暗门密码。
验证者(Victor)在洞穴外，随机喊Peggy从A或B出来。
Peggy每次都能从正确方向出来。
经过多轮验证，Victor确信Peggy知道暗门，但Victor自己仍不知道暗门位置。

核心：通过多轮随机挑战建立"不可能只是运气好"的可信度。
```

### 5.2 主要方案对比

| 方案 | 证明大小 | 验证时间 | 可信设置 | 量子安全 |
|------|----------|----------|----------|----------|
| Groth16 | ~200B | O(1) | 需要 | 否 |
| Plonk | ~500B | O(1) | 通用 | 否 |
| STARK | ~100KB | 快 | 不需要 | 是 |
| Bulletproofs | O(log n) | 慢 | 不需要 | 否 |

## 6. 经典问题

- 可信设置的"有害废料"管理——多方计算仪式（MPC Ceremony）确保只要至少一方诚实销毁就安全
- 证明生成 vs 验证的开销不对称——证明生成可能慢 10^6×
- 递归证明——一个证明验证另一个证明的正确性，用于区块链的证明聚合
