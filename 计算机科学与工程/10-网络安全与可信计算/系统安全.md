# 系统安全

## 1. 一句话定义

系统安全关注操作系统和软件层面的安全防护，包括内存安全、权限控制、漏洞利用防御和软件供应链安全。

## 2. 核心问题

- 如何防止攻击者利用软件漏洞获取系统控制权？
- 如何在默认不安全的环境中构建防御层？
- 如何验证软件来源的可信性？

## 3. 知识框架

| 领域 | 核心内容 | 代表性技术 |
|------|----------|------------|
| 内存安全 | 防止缓冲区溢出、UAF、双重释放 | ASLR、DEP/NX、Stack Canary |
| 权限控制 | 最小权限、强制访问控制 | SELinux、AppArmor、Capabilities |
| 沙箱 | 隔离不可信代码 | seccomp、gVisor、WebAssembly |
| 软件供应链 | 依赖安全、签名验证 | SBOM、SLSA 框架 |
| 漏洞管理 | CVE、CVSS、补丁管理 | 漏洞扫描、风险管理 |

## 4. 关键概念

- **内存破坏漏洞**：缓冲区溢出（栈/堆）、Use-After-Free、Double Free——C/C++ 遗留的最危险漏洞类型
- **防御技术栈**：Stack Canary（栈保护）→ ASLR（地址随机化）→ DEP/NX（数据不可执行）→ CFI（控制流完整性）
- **最小权限原则**：任何实体只应拥有完成任务所需的最小权限
- **沙箱逃逸**：攻击者在受限环境中突破隔离执行任意代码
- **侧信道攻击**：通过物理实现特征（时序、功耗、电磁）而非算法缺陷获取信息——Spectre/Meltdown 是典型

## 5. 典型机制

### 5.1 内存攻击与防御演进

```
攻击技术：栈溢出 → 堆利用 → ROP → JOP → Speculative Execution
防御技术：NX 位 → ASLR → Stack Canary → CFI → CET (Intel)
```

### 5.2 漏洞评分 CVSS

| 指标 | 内容 |
|------|------|
| 攻击向量 | 网络/邻接/本地/物理 |
| 攻击复杂度 | 低/高 |
| 权限要求 | 无/低/高 |
| 用户交互 | 无/需要 |
| 影响 | CIA 各维度评分 |

## 6. 经典问题

- C/C++ 的内存安全——70% 的浏览器和 OS 内核漏洞来自内存错误
- 依赖地狱——npm/PyPI 等注册表引入的供应链风险
- 补丁管理的两难——快速修补（可能引入新 bug）vs 充分测试（留出攻击窗口）
- 遗留系统的安全债务

## 7. 工程实践

- 使用 AddressSanitizer（ASan）检测内存错误
- 在 Linux 上配置 seccomp 限制进程的系统调用
- 使用 `checksec` 检查二进制文件的防御机制开启情况
- 了解 CVE 编号系统和 CVSS 评分方法

## 8. 与其他主题的关系
