# 前端工程化

## 1. 一句话定义

前端工程化关注如何系统化地构建、测试、优化和部署前端应用，覆盖 TypeScript 类型系统、构建工具链、模块化、性能优化和部署策略。

## 2. 核心问题

- 如何在大型 JavaScript 项目中保证代码质量？
- 构建工具如何优化打包体积和加载性能？
- 如何从传统多页面过渡到现代前端架构？

## 3. 知识框架

| 主题 | 核心内容 | 关键工具 |
|------|----------|----------|
| TypeScript | 静态类型系统、接口、泛型 | tsc、tsconfig |
| 构建工具 | 打包、转译、摇树、代码分割 | Vite、Turbopack、esbuild |
| 包管理 | 依赖管理、工作空间 | pnpm、yarn、bun |
| 代码质量 | 格式化、静态分析 | ESLint、Prettier |
| 测试 | 组件测试、E2E | Vitest、Playwright |
| 性能优化 | 懒加载、预加载、资源优化 | Lighthouse、Web Vitals |

## 4. 关键概念

- **TypeScript**：JavaScript + 静态类型——在编译时捕获类型错误，大型项目的事实标准
- **Tree Shaking（摇树优化）**：移除未使用的代码——依赖 ES Module 的静态导入特性
- **代码分割（Code Splitting）**：将代码拆分为按需加载的块——减小首屏加载体积
- **HMR（热模块替换）**：代码变更后不刷新页面直接替换模块——保持应用状态
- **Core Web Vitals**：Google 的 Web 性能标准——LCP（加载）、INP（交互）、CLS（视觉稳定性）

## 5. 典型实践

### 5.1 现代前端工具链

```
源码 (TS/JSX/CSS)
    ↓
编译器/转译器 (esbuild/swc → TS→JS, JSX→JS)
    ↓
打包器 (Vite/Rollup → 合并+优化)
    ↓
开发服务器 (HMR + 按需编译)
    ↓
生产构建 (压缩 + 代码分割 + 资源哈希)
```

### 5.2 构建工具演进

| 工具 | 特点 | 速度 |
|------|------|------|
| Webpack | 生态最丰富，配置复杂 | 较慢 |
| Vite | 开发时 ESM 按需，生产用 Rollup | 极快 |
| esbuild | Go 编写，原生速度 | 极快 |
| Turbopack | Rust 编写，Next.js 官方 | 极快 |
