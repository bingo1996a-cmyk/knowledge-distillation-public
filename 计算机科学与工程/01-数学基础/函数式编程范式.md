# 函数式编程范式

## 1. 一句话定义

函数式编程（Functional Programming, FP）将计算视为数学函数的求值，强调不可变数据、纯函数和声明式表达，避免共享状态和可变数据——核心思想是"用计算来描述是什么，而非命令式步骤来描述怎么做"。

## 2. 核心问题

- 如何在没有可变状态的情况下表达计算？
- 副作用（IO、状态、异常）如何在纯函数式模型中处理？
- 函数式编程如何使程序更易推理和并发？

## 3. 知识框架

| 概念 | 核心思想 | 编程中的体现 |
|------|----------|-------------|
| 纯函数 | 相同输入→相同输出，无副作用 | 引用透明性 |
| 不可变性 | 数据创建后不可修改 | 持久化数据结构 |
| 高阶函数 | 函数作为参数和返回值 | map、filter、reduce |
| 代数数据类型 | 积类型+和类型，模式匹配 | Option、Result、Either |
| 函子/单子 | 抽象组合模式 | IO、State、async |
| 惰性求值 | 需要时才计算 | Haskell 的惰性 |

## 4. 关键概念

- **纯函数（Pure Function）**：无副作用 + 确定性——可以自由地缓存、并行化、乱序执行、惰性计算
- **引用透明性（Referential Transparency）**：表达式可替换为其求值结果而不改变程序行为——推导式推理的基础
- **不可变数据（Immutable Data）**：修改操作返回新数据而非原地修改——通过结构共享（如 Trie）实现高效持久化
- **高阶函数（Higher-Order Function）**：函数接收函数或返回函数——组合和抽象的基础
- **代数的数据类型（ADT）**：积类型（AND: 同时包含多个值）和类型（OR: 是几个变体之一）——"让非法状态不可表示"

## 5. 典型机制

### 5.1 副作用建模方式

```
纯函数式（Haskell）：用单子封装副作用
  main :: IO ()  — "程序是描述如何与外部世界交互的 IO 单子值"

多范式（Rust/Scala）：隔离副作用但允许命令式代码
  fn read_file() -> Result<String, Error>
  
响应式（Elm/React）：状态 → UI 的纯函数变换
  view: Model → Html
```

### 5.2 多语言中的函数式特性

| 语言 | 函数式特性 |
|------|-----------|
| Haskell | 纯函数式、惰性、单子 |
| Scala | 融合 OOP+FP、Cats/ZIO |
| Rust | 不可变默认、ADT(enum)、迭代器链 |
| JavaScript/TS | 高阶函数、闭包、不可变库(Immer) |
| Python | 列表推导、lambda、functools |
| Clojure | Lisp on JVM、不可变数据结构 |

## 6. 经典问题

- 性能——持久化数据结构和惰性求值有开销
- 学习曲线——从命令式思维切换到声明式思维的难度
- 纯度边界——最终需要和外部世界交互，单子堆栈的复杂性
- 尾递归优化——函数式循环范式的性能基础

## 7. 工程实践

- 用 `map`/`filter`/`reduce` 替代显式循环
- 使用不可变数据结构和结构共享
- 用 `Option`/`Result` 替代 `null`/异常
- 将副作用推到"系统的边缘"，保持核心逻辑纯函数化

## 8. 与其他主题的关系

| 相关主题 | 关系 |
|----------|------|
| 类型系统 | 代数数据类型是 FP 类型系统的基石 |
| 范畴论 | 函子、单子等抽象源于范畴论 |
| 并发模型 | 不可变性天然避免数据竞争 |
| 设计模式 | 函数式语言中大部分 GoF 模式被函数和 ADT 替代 |
