# 类型系统

## 1. 一句话定义

类型系统（Type System）是编程语言中为表达式分配类型的形式规则，用于在编译时静态地检测和预防程序错误——"在程序运行前排除一类错误"。

## 2. 核心问题

- 如何在不过度限制表达能力的前提下静态排除更多的运行时错误？
- 类型系统精确性的界限在哪里（可判定性 vs 表达能力）？
- 不同类型系统（静态/动态/渐进/依赖）各自的权衡是什么？

## 3. 知识框架

| 层次 | 核心内容 | 代表性语言/系统 |
|------|----------|-----------------|
| 简单类型 | 基本类型、函数类型 | C、Pascal |
| 参数多态 | 类型变量、泛型 | Java Generics、Rust |
| 子类型 | 类型层次、多态 | Java、TypeScript |
| 代数数据类型 | 积类型 + 和类型 | Haskell、Rust enum |
| 依赖类型 | 类型依赖于值 | Idris、Lean、Coq |
| 线性类型 | 资源使用追踪 | Rust（仿射类型）、Linear Haskell |

## 4. 关键概念

- **静态 vs 动态 vs 渐进类型**：静态（编译时检查）、动态（运行时检查）、渐进（可选类型，可逐步添加，如 TypeScript）
- **类型推断（Type Inference）**：自动推导类型无需显式注解——Hindley-Milner 系统（ML/Haskell）→ 局部推断（Rust/Swift）
- **可靠性（Soundness）**：如果类型检查通过，程序不会进入"未定义行为"——不是所有语言都可靠（C/C++ 不可靠）
- **完备性（Completeness）**：每个安全程序都能通过类型检查——总是牺牲完备性换取可靠性
- **多态（Polymorphism）**：参数多态（泛型，"对任意类型 T"）、特设多态（函数重载）、子类型多态（接口/继承）

## 5. 典型机制

### 5.1 类型系统谱系

```
无类型(λ演算) → 简单类型 → 参数多态(Hindley-Milner)
                                  ↓
                           System F（∀ 类型）
                           ↓                  ↓
                     System Fω（高阶类型）  依赖类型（Π 类型）
                           ↓                  ↓
                     Haskell/GHC Core      Coq/Lean/Idris
```

### 5.2 类型安全对比

| 语言 | 类型系统 | 可靠？ | 特点 |
|------|----------|--------|------|
| C | 弱静态 | 否 | 无保护，性能最优 |
| Java | 静态 + 子类型 | 基本可靠 | 成熟，冗长 |
| Haskell | 静态 + 参数多态 | 可靠 | 纯函数式 |
| Rust | 静态 + 所有权 | 可靠 | 无 GC 的安全系统编程 |
| TypeScript | 渐进 | 基本可靠 | JS 的超集 |

## 6. 经典问题

- 可靠性与类型安全的代价——运行时检查（数组越界）和静态限制（借用检查器）
- Hindley-Milner 类型推断的限制——不能推断高阶多态
- 子类型+泛型的协变/逆变——Java 通配符的复杂性来源

## 7. 工程实践

- 理解 TypeScript 的类型体操——条件类型、映射类型、模板字面量类型
- 比较在不同类型系统中实现同一功能的代码差异
- 用 Rust 体验所有权和借用检查如何防止悬垂指针和数据竞争
