# Petri 网、抽象解释与程序逻辑

## 作用

这一主题研究如何形式化表达并发系统、如何用近似语义分析程序行为，以及如何证明程序满足给定规范。

## 三类核心对象

- Petri 网（Petri Net）：表达并发、同步、资源竞争和事件流
- 抽象解释（Abstract Interpretation）：在安全近似下分析程序可能状态
- 程序逻辑（Program Logic）：如 Hoare Logic，用形式规则推导程序正确性

## 一个典型 Hoare 三元组

$$
\{P\}\ C\ \{Q\}
$$

表示若程序片段 $C$ 执行前满足前置条件 $P$，则执行后满足后置条件 $Q$。

## 为什么重要

### 1. 它把“程序会不会出错”转化为可验证问题

### 2. 它对编译器、静态分析、并发协议和安全验证极其关键

### 3. 它连接逻辑、自动机、图结构和程序语义

## 最小例子

### 例 1：Petri 网 — 简单生产者-消费者系统

**问题陈述**：一个生产者生产物品放入缓冲区（容量为 2），一个消费者从缓冲区取出物品消费。用 Petri 网建模该并发系统，并分析是否会出现缓冲区溢出。

**数学表达**：Petri 网 $N=(P,T,F,M_0)$，其中 $P$ 为库所集，$T$ 为变迁集，$F$ 为流关系，$M_0$ 为初始标识。

**计算/推理步骤**：

1. 定义库所：$P_1$ = "生产者就绪"，$P_2$ = "缓冲区有空间"（初始 2 个令牌表示容量 2），$P_3$ = "缓冲区有物品"，$P_4$ = "消费者就绪"。
2. 定义变迁：$T_1$ = "生产并放入"（消耗 $P_1$ 和 $P_2$ 各 1 令牌，产生 $P_1$ 和 $P_3$ 各 1），$T_2$ = "取出消费"（消耗 $P_4$ 和 $P_3$ 各 1，产生 $P_4$ 和 $P_2$ 各 1）。
3. 初始标识 $M_0 = (1,2,0,1)$。
4. 可达性分析：
   - 触发 $T_1$：$M_1 = (1,1,1,1)$
   - 从 $M_1$ 可触发 $T_2$ 回到 $M_0$，或再次触发 $T_1$ 得 $M_2 = (1,0,2,1)$
   - 从 $M_2$ 只能触发 $T_2$ 得 $M_1$
5. 缓冲区最大物品数为 2（可达标识中 $M(P_3)\le 2$），永不溢出。

**结果解读**：Petri 网用库所中的令牌数量直观表示资源可用性，用变迁的触发模拟并发事件。本例中缓冲区容量由 $P_2$ 的初始令牌数（2）编码，系统的安全性质（不溢出）可通过可达图进行形式验证。

### 例 2：Hoare 逻辑 — 两数交换程序验证

**问题陈述**：用 Hoare 逻辑证明以下程序正确交换两个变量的值：
```
t := x;  x := y;  y := t
```
即前置条件为 $\{x = X \land y = Y\}$，后置条件为 $\{x = Y \land y = X\}$。

**数学表达**：需要找到中间断言，应用 Hoare 赋值公理和顺序组合规则构造证明。

**计算/推理步骤**：

1. 从后向前推导中间断言：
   - 最后语句 `y := t` 的后置条件是 $\{x = Y \land y = X\}$。由赋值公理，其前置条件为 $\{x = Y \land t = X\}$。
   - 中间语句 `x := y` 的后置条件是 $\{x = Y \land t = X\}$。其前置条件为 $\{y = Y \land t = X\}$。
   - 第一条语句 `t := x` 的后置条件是 $\{y = Y \land t = X\}$。其前置条件为 $\{y = Y \land x = X\}$。

2. 原始前置条件 $\{x = X \land y = Y\}$ 蕴含 $\{y = Y \land x = X\}$，证明成立。

3. 完整证明树：
   $$
   \frac{\{x = X \land y = Y\}\;t:=x\;\{y = Y \land t = X\}}{\frac{\{y = Y \land t = X\}\;x:=y\;\{x = Y \land t = X\}}{\frac{\{x = Y \land t = X\}\;y:=t\;\{x = Y \land y = X\}}{\{x = X \land y = Y\}\;t:=x;\,x:=y;\,y:=t\;\{x = Y \land y = X\}}}}
   $$

**结果解读**：这是 Hoare 逻辑最基础的验证示例。关键技巧是从后置条件向后推导中间断言（逆向推理），赋值公理 $\{P[e/x]\}\;x:=e\;\{P\}$ 保证了每一步的正确性。即使是最简单的赋值程序，形式验证也需要精确的断言推导，这对理解程序逻辑的严谨性至关重要。

## 风险与约束

- 形式模型过弱会漏报，过强会不可计算
- 并发系统状态空间爆炸是基本难点
- 静态分析通常给保守结论，不等于完全精确语义
