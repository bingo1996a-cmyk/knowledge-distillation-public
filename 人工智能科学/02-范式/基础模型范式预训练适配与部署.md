# 基础模型范式：预训练、适配与部署

## 1. 定位

这一页讨论“基础模型（foundation model）”为什么应该被看成一种**范式（paradigm）**，而不是单一模型类别。

它关注的不是某一具体架构，而是完整链条：

`大规模数据组织 -> 预训练目标 -> 通用能力层 -> 适配机制 -> 后训练 -> 部署与治理`

## 2. 为什么基础模型是范式而不是模型名

如果只把基础模型理解为“大参数 Transformer”，会遗漏真正关键的变化：

1. 训练数据从任务专用转向大规模多源语料；
2. 学习目标从单任务监督转向自监督 / 生成式预训练；
3. 使用方式从“一任务一模型”转向“预训练 + 适配 + 工具调用”；
4. 工程组织从单点训练转向持续评测、后训练和发布门禁。

## 3. 范式的核心结构

### 3.1 预训练层

目标是学习可迁移的通用表征或生成能力。典型目标包括：

- 自回归建模；
- 掩码建模；
- 对比学习；
- 多模态对齐；
- 轨迹或动作序列建模。

### 3.2 适配层

预训练后通常还需要：

- 全参数微调；
- 参数高效适配（如 adapter / LoRA）；
- prompt / prefix / in-context adaptation；
- retrieval-augmented adaptation；
- tool-augmented adaptation。

### 3.3 后训练层

为了让模型进入真实系统，还需要：

- 指令跟随；
- 偏好优化；
- 安全对齐；
- 长上下文与记忆控制；
- 测试时计算与 verifier 机制。

### 3.4 部署层

基础模型真正困难的部分不在预训练本身，而在部署后：

- latency / throughput；
- 观测、审计与监测；
- policy enforcement；
- data governance；
- release gate 与 incident response。

## 4. 与传统监督学习范式的区别

### 4.1 目标函数层面

传统监督学习强调针对单任务误差最小化；基础模型范式更强调：

- 学到可迁移能力；
- 支持大量下游任务；
- 在交互、工具和环境反馈下被重新组织。

### 4.2 系统层面

传统范式通常是：

`训练 -> 测试 -> 部署`

基础模型范式更接近：

`数据治理 -> 预训练 -> 对齐/后训练 -> 系统接入 -> 运行时治理 -> 持续更新`

## 5. 为什么它推动了 AI 研究重心变化

基础模型范式改变了研究问题的重心：

- 从“更好的单任务模型”转向“更稳定的通用能力层”；
- 从“模型结构优先”转向“数据、目标、后训练与系统共设计”；
- 从“离线 benchmark”转向“运行时治理与可审计性”。

## 6. 失败模式

1. 预训练数据分布与部署环境严重失配；
2. 下游迁移好，但 calibration 差；
3. 对齐后任务能力退化；
4. 工具调用增强了能力，也扩大了错误外部化风险；
5. 测试时计算策略与 latency budget 冲突。

## 7. 与深度学习、RL、agent 的关系

- 它是深度学习范式的扩展，而不是替代；
- 它与 RL 在后训练、偏好优化和 deliberation 中交叉；
- 它与 agent 系统在工具使用、记忆、规划、审批流和治理层耦合。

## 8. 研究切口

1. **预训练目标与可验证推理的关系**；
2. **foundation model 的 runtime governance**；
3. **多模态基础模型与科学 / 航天系统**；
4. **基础模型的高风险部署审计**；
5. **基础模型与小模型协同**：在资源受限场景下的层级架构。
