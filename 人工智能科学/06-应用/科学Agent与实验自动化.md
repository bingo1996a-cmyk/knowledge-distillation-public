# 科学智能体（Scientific Agents）与实验自动化

> **阅读顺序**：本页是 scientific agent 系列的起点，定义核心概念与闭环能力。建议按以下顺序阅读：(1) 本页 → (2) [实验仪器/平台集成](./scientific-agents-and-lab-instrument-integration.md) → (3) [协议编译器与中间件](./scientific-agent-protocol-compilers-registry-services-and-lab-middleware.md) / [协议注册表与校准模式](./scientific-agent-protocol-registries-and-calibration-schemas.md)（并读）→ (4) [协议映射与治理](./scientific-agents-protocol-mapping-sample-tracking-and-calibration-governance.md)。

## 定位

这篇笔记关注的不是一般科研助手，而是能够进入“假设提出—文献检索—实验设计—工具调用—结果分析—记录回写”闭环的 scientific agent。

它处于以下几条主线的交叉处：

- 大模型（large language model, LLM）与工具调用；
- 科学机器学习（scientific machine learning, SciML）；
- 自动化实验平台与机器人实验室；
- 研究流程中的审计、复现与治理。

## 一、概念边界

### 1. scientific agent 不等于论文问答助手

论文问答、文献综述、代码解释只是外围能力。更严格的 scientific agent 至少需要：

- 处理研究目标；
- 生成可执行计划；
- 调用外部工具或仪器；
- 读取实验结果；
- 调整下一轮方案；
- 保留审计轨迹。

### 2. 自动化实验不等于完全无人化

更现实的结构通常是：

- 低风险流程自动化；
- 关键假设与关键阈值由人审批；
- 高代价实验需人工复核；
- 数据写回、版本记录和异常终止可追踪。

### 3. 科学闭环与一般 agent 的关键差异

一般业务 agent 更强调任务完成率；scientific agent 还要额外满足：

- 结论可复现；
- 证据链可检查；
- 仪器与数据有校准语境；
- 失败实验也要可解释。

## 二、一个最小科学闭环

一个更贴近科研流程的 agent 闭环可写成：

\[
\text{Problem} \rightarrow \text{Hypothesis} \rightarrow \text{Plan} \rightarrow \text{Execution} \rightarrow \text{Measurement} \rightarrow \text{Analysis} \rightarrow \text{Update}
\]

若把它写成迭代过程：

\[
\mathcal{H}_{k+1} = U\big(\mathcal{H}_k, D_k, A_k, C_k\big)
\]

其中：

- \(\mathcal{H}_k\)：第 \(k\) 轮假设集合；
- \(D_k\)：实验数据；
- \(A_k\)：分析结果；
- \(C_k\)：约束、预算与人工反馈；
- \(U\)：假设更新算子。

scientific agent 的本质，就是实现这个更新过程中的多个子模块。

## 三、系统结构

### 1. 问题建模层

输入通常包括：

- 研究目标；
- 理论背景；
- 已知约束；
- 实验预算；
- 可调用工具列表。

### 2. 文献与知识层

需要管理：

- 论文与专利；
- 实验协议；
- 仪器说明；
- 历史实验记录；
- 负结果与失败案例。

### 3. 假设与计划层

scientific agent 不应只“提点子”，还应输出：

- 可检验假设；
- 变量定义；
- 对照组与控制变量；
- 成功/失败判据；
- 预算与优先级。

### 4. 执行层

执行对象可能是：

- 仿真器；
- 代码实验；
- 计算工作流；
- 机器人实验平台；
- 科学仪器接口。

### 5. 分析层

需要处理：

- 数据清洗；
- 不确定性评估；
- 可视化；
- 统计检验；
- 与既有理论/文献比对。

### 6. 审计与回写层

必须记录：

- 用了哪个模型；
- 使用了哪些工具；
- 参数和提示词；
- 数据版本；
- 仪器状态；
- 人工审批节点。

## 四、三种典型 scientific agent 形态

### 1. 文献驱动型

主要做：

- 研究问题澄清；
- 文献梳理；
- 假设生成；
- 方案比较。

风险较低，但容易停留在“聪明的写作助手”。

### 2. 仿真驱动型

主要做：

- 代码生成；
- 参数搜索；
- 实验组织；
- 结果分析；
- 自动写作草稿。

这一类最容易在机器学习、计算材料、气候建模、控制仿真中落地。

### 3. 仪器与实验驱动型

主要做：

- 调用实验设备；
- 协调样品制备、测量、分析；
- 在实验过程中在线修正计划。

这一类最强，但也最需要权限控制、审批流和安全壳。

## 五、关键技术模块

### 1. 任务图与工作流编排

科研流程不是一次性回答，而是阶段性工作流。需要：

- DAG 或状态机表示；
- 条件分支；
- 失败回滚；
- 子任务重试；
- 资源预算。

### 2. 工具调用与仪器封装

工具调用必须是**语义层 + 协议层**双重对齐：

- 模型知道什么时候调用；
- 系统知道怎么安全调用；
- 调用后结果能回写到状态与记忆。

### 3. 实验设计与主动学习

更高级的系统会把下一轮实验选择写成：

\[
x_{k+1}^{*} = \arg\max_{x \in \mathcal{X}} \; \alpha(x \mid \mathcal{D}_k)
\]

其中 \(\alpha\) 可以是贝叶斯优化（Bayesian optimization）中的 acquisition function，也可以是信息增益、最大不确定性或多目标效用。

### 4. 不确定性与证据管理

scientific agent 不能只给结论，还要给：

- 不确定性范围；
- 支持证据；
- 数据质量说明；
- 是否需要额外实验。

### 5. 人机协作审批

在真实实验环境中，至少应设定：

- 高成本实验审批；
- 高风险药剂/设备步骤审批；
- 超预算中止；
- 结论发布前人工复核。

## 六、常见失败模式

### 1. 把文献相关性误当科学新颖性

系统可能很会检索，但不会真正识别“可检验的新问题”。

### 2. 把实验自动执行误当科学发现

自动跑实验并不等于提出了合理假设，更不等于给出可靠解释。

### 3. 忽略仪器与协议语境

现实实验的失败常来自：

- 样品条件；
- 仪器漂移；
- 校准不充分；
- 人工操作隐含前提。

### 4. 只保存成功结果

科学流程里，失败样本、无效参数区、负结果和异常日志同样重要。

### 5. 没有审计链

若不能回放：

- 是谁提出假设；
- 谁批准实验；
- 用了哪个版本模型；
- 哪轮实验数据支撑了结论；

则该系统很难进入高质量科研流程。

## 七、评测指标

建议至少分六组：

### 1. 研究流程指标

- 从目标到可执行方案的时间；
- 计划成功执行率；
- 失败回滚成功率；
- 人工干预频次。

### 2. 科学价值指标

- 假设有效率；
- 实验信息增益；
- 新颖性筛选质量；
- 结果复现率。

### 3. 工具与执行指标

- API / 仪器调用成功率；
- 参数有效性；
- 预算控制；
- 资源利用率。

### 4. 数据质量指标

- 数据完整度；
- 版本可追踪性；
- 标签/元数据一致性；
- 异常记录覆盖率。

### 5. 治理指标

- 审批覆盖率；
- 高风险动作拦截率；
- 审计日志完整率；
- 结论可追溯性。

### 6. 人机协作指标

- 专家修订量；
- 专家采纳率；
- 误导性建议比例；
- 结论可信度评分。

## 八、面向博士阶段研究的切口

### 1. scientific agent 的任务图表示

如何把研究问题、实验步骤、验证条件和失败回退表示成可学习、可执行、可审计的任务图。

### 2. 模型与实验平台的接口层

如何把 LLM / planner 与仿真器、仪器、数据库、安全壳对接。

### 3. 科学闭环中的不确定性传播

从假设、实验设计、测量噪声到结论置信区间，如何做一致性建模。

### 4. 审计与复现实验设计

如何把 scientific agent 的 every-step trace 转换为研究可复现证据。

### 5. 面向控制与复杂系统的 scientific agent

这对你的主线尤其重要：

- 自动组织仿真实验；
- 自动做消融与参数扫描；
- 自动记录实验配置；
- 自动回写结果到论文草稿与研究日志。

## 九、公开趋势与可核验方向

近两年公开论文与系统演示已经表明，scientific agent 正从“文献助手”向“闭环实验系统”发展，至少出现了三类清晰趋势：

1. **端到端研究自动化**：从想法、代码、实验到写作的自动组织。
2. **人机协同仪器操作**：agent 进入真实科学仪器与自动化实验台。
3. **高风险流程中的 human-in-the-loop**：关键环节保留人工控制与审批。

这些趋势说明，scientific agent 的真正挑战并不只是更强模型，而是更严格的系统工程、实验设计和治理结构。

## 十一、结论

scientific agent 不是“会写论文的模型”，而是科研闭环中的一个可审计执行体。

其价值不在于替代科学家，而在于把：

- 问题组织；
- 文献与知识管理；
- 实验设计；
- 工具调用；
- 结果分析；
- 研究日志回写

连接成可复现、可检查、可迭代的研究基础设施。
