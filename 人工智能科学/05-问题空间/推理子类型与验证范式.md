# 推理子类型与验证范式

## 定位

本页是对"推理、搜索与验证问题空间"的深度展开。推理不是一个单一种类——不同类型的推理具有截然不同的知识来源、错误模式和验证方法。本页详细分析演绎、归纳、溯因、类比和常识推理五种子类型及其对应的验证范式。

## 一、演绎推理

演绎推理从一般规则和特定前提出发，推导出必然成立的结论。如果前提为真且推理规则正确，结论必然为真。

**典型任务：** 定理证明（数学）、程序验证（形式化方法）、逻辑推理（法律推理、规则引擎）、约束求解（SAT/SMT）。

**核心挑战：**
- 搜索空间爆炸。即使小型逻辑系统，推理步骤的组合数也会随前提数量指数级增长。解决策略包括启发式搜索（如 E-prover 的自定义权重）和神经引导搜索（用神经网络选择下一步规则）。
- 不完全知识。现实世界的推理很少拥有一阶逻辑所需的全部公理。需要合理假设和缺省推理。
- 验证可判断性。并不是所有逻辑系统都是可判定的——一阶逻辑半可判定，高阶逻辑不可判定。

**验证范式：** 形式验证是最可靠的方法——每一步推理都可被独立验证器检查。Lean、Coq、Isabelle 等交互式定理证明器提供逐行验证。自动化验证工具（SAT 求解器、SMT 求解器、一等逻辑自动化证明器）用于大规模搜索，但可能需要人工提供引理或归纳模式。

## 二、归纳推理

归纳推理从具体观测中推断一般规律或模式。结论不是必然成立的，而是高概率的。

**典型任务：** 科学假设生成（从实验数据中发现模式）、统计学习（从未知分布中学习分类/回归函数）、程序综合（从输入-输出示例中归纳程序）、数学猜想（从数值实验中发现定理候选）。

**核心挑战：**
- 过拟合与泛化。归纳本质上是病态问题——有限观测对应无限多可能的规律。选择偏差、衡量偏差和确认偏差是最常见的归纳陷阱。
- 因果推断。相关性不等于因果性。归纳推理发现的模式统计上成立但因果上可能无关，需要额外的干预实验或因果图分析来区分。
- 组合多样性与样本效率。在程序综合中，从很少的示例中找到正确的程序在搜索空间极大时非常困难。

**验证范式：** 归纳推理的验证需要"归纳-验证"双循环模式：归纳阶段生成候选规律（假设或程序），验证阶段用留出数据、交叉验证、反例搜索或逻辑约束来检验其有效性。这与"猜测-检验"的科学方法论高度一致。

## 三、溯因推理

溯因推理从观测到的现象出发，推断最可能的解释或原因。它是诊断性思维的典型代表。

**典型任务：** 医疗诊断（从症状推断疾病）、故障定位（从系统异常推断根因）、反事实解释（"如果做 X 是否还会发生 Y"）、科学发现中的假设生成和后验分析。

**核心挑战：**
- 解释数量与选择。同一现象通常对应多个可能的解释，需要在似然率、简单性和解释力之间做权衡——这是奥卡姆剃刀的操作化难题。
- 因果推断的逆向性质。从果溯因天然地比从因推果更困难，因为多个原因可能导致同一结果，且原因之间可能存在交互作用（例如多种疾病共同导致一组症状）。
- 概率推理中的先验依赖。溯因推理结果高度依赖先验知识——先验分布的选择会显著改变最可能解释。

**验证范式：** 溯因推理的验证通常需要设计鉴别性实验——在多个可能的解释之间通过额外观测区分优劣。在不可实验的场景下（如事后分析），验证依赖于理论一致性（解释是否与已知知识矛盾）和预测能力（解释是否对新观测有预测力）。

## 四、类比推理

类比推理将已知领域的知识结构映射到新领域。它是人类认知中最重要的泛化机制之一。

**典型任务：** 类比问题求解（将已知领域策略映射到新问题）、迁移学习（从源任务中提取可重用知识）、类比归因（"这是一个人的 X 版本"）、创意生成和新颖设计。

**核心挑战：**
- 映射的选择。两个领域之间有无穷多潜在映射关系，需要选择语义上有意义的映射——这依赖领域知识、抽象层次判断和整体结构的保持。
- 类比与基线的区分。类比只是推理启发式，不是保证——两个问题可能表面相似但在深层结构上完全不同。误用类比是常见的推理错误。
- 跨领域知识表示。类比需要统一的知识表示形式（如结构映射理论中的谓词演算），但不同领域的知识表示方法差异很大。

**验证范式：** 类比推理的验证检查映射的准确性（映射是否保持了源领域的结构关系）、迁移效果的实证评估（在新领域中类比方案是否确实有效）、以及消融研究（不使用类比直接求解，对比差异）。

## 五、常识推理

常识推理涉及关于日常世界的普通知识——物体物理属性、社会规范、因果关系、默认假设——而不需要被明确告知。

**典型任务：** 阅读理解中的隐含推断、人机交互中的隐含意图理解、物理常识（如果一个物体没有支撑就会下落）、社交常识（打断别人说话通常不礼貌）。

**核心挑战：**
- 表示瓶颈。常识知识的范围几乎无限——无法通过手工规则或有限数据集穷举覆盖。这是符号主义时代遭遇的根本困难之一。
- 默认性与非单调性。常识推理通常依赖于"除非有相反证据"的假设（默认规则），当新证据出现时需要撤销旧结论。
- 文化依赖与歧义。常识有文化特异性。在美国的常识在中国可能不适用，这使得跨文化常识系统的构建极为困难。

**验证范式：** 常识推理的验证是最困难的——因为常识本身没有完整的真值表。通常的方法包括：基于标注数据集的评估（如 Winograd Schema、CommonsenseQA）、对抗性测试（构造常识违反的情境检查系统是否识别）、和人类判断基准（在开放域中抽样评估常识推理的合理性）。

## 六、跨类型推理的融合

实际任务常常同时涉及多种推理类型。以科学发现为例：

1. **观测** → 感知/模式识别
2. **假设生成** → 归纳/溯因推理
3. **推导假设的预测** → 演绎推理
4. **设计与运行实验** → 溯因推理的验证阶段
5. **类比迁移** → 将结果推广到相关领域

在系统设计中，纯粹的推理管线很少存在。推理框架应支持类型的动态切换和协作，而非局限于单一推理模式。
