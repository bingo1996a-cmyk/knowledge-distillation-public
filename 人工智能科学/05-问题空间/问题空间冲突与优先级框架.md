# 问题空间冲突与优先级框架

## 定位

大多数实际任务不属于单一的纯问题空间，而是多个问题空间的复合。当同一个任务同时涉及感知、推理和规划时，如何确定主问题空间、如何处理不同空间之间的交互与冲突，就成为工程决策的关键。本页提供一个可操作的判断框架。

## 为什么冲突会发生

问题空间的定义维度包括输入形态、输出形态、目标定义方式、环境反馈模式和中间计算结构。实际任务往往在这些维度的多个取值之间同时存在。以自动驾驶为例：

- 感知问题空间：从摄像头和 LiDAR 中提取目标、车道、交通标志；
- 规划问题空间：在动态环境中选择安全的行驶轨迹；
- 推理问题空间：遵守交规、预判其他交通参与者的意图；
- 控制问题空间：通过转向、加速和制动执行规划轨迹；
- 评估问题空间：在离线数据上测试规划算法，在真实道路上测试端到端系统。

如果只按其中一个问题空间设计系统（如只把它当感知问题），其他问题空间被忽略，系统会在未覆盖的方面出问题。这不是"没找准一个正确的问题空间"，而是任务本质上是多空间的。

## 问题空间复合的三种模式

### 1. 管道模式（Pipeline）

问题空间按顺序排列，前一个的输出是后一个的输入。各空间之间有清晰的接口边界。

```
感知 → 推理/理解 → 规划/决策 → 控制/执行
```

管道模式的结构清晰，各阶段可独立开发和评测，但误差会逐级累积——感知阶段的微小错误经过推理和规划会被放大为决策错误。管道设计的关键决策包括：接口协议设计（传递什么信息、什么格式）、误差传递分析和容错机制。

### 2. 紧耦合模式（Tight Coupling）

多个问题空间共享一个表示层，在表示空间中同时推理。端到端自动驾驶（raw pixels → control commands）和视觉语言模型（image + text → text）属于此类。

紧耦合模式避免了误差累积（因为中间表示在决策目标下联合优化），但代价是缺乏可分解性和可解释性——当系统出错时很难定位问题来自感知、推理还是控制的哪一部分。评测也只能做端到端评测，不能分段调试。

### 3. 混合模式（Hybrid）

部分问题空间紧耦合（如感知+推理共享 Transformer 表示层），部分空间外部环路控制（如规划器和安全约束层独立于神经网络）。混合模式是实际工程中最常见的模式。

典型例子：大语言模型作为推理引擎（紧耦合的语言理解和推理），连接外部工具（知识检索、代码执行、物理模拟）作为独立的检查或执行层。工具的添加并不改变 LLM 内部的问题空间复合结构，而是在系统架构层面增加了一个"外部验证"问题空间。

## 主问题空间判断框架

当面对复合任务时，使用以下流程确定主问题空间：

**第一步：列出任务涉及的问题空间。** 遍历七个核心问题空间，对每个回答"这个任务是否涉及此类操作？"。自动驾驶会命中 3-4 个。

**第二步：确定决策链的"瓶颈环节"。** 哪个问题空间的错误会直接导致任务失败？自动驾驶的瓶颈通常是感知和规划——感知错误导致看不到障碍物，规划错误导致撞车。控制错误在正常工况下较少成为瓶颈。

**第三步：按瓶颈环节确定主空间。** 将系统设计的主要精力和评测资源集中在瓶颈环节的问题空间上。这不是说其他空间不重要，而是说设计逻辑的起点从瓶颈问题空间展开。

**第四步：对非主空间，选择最经济的处理策略。** 要么采用现成的工程方案（如感知用成熟的目标检测模型），要么缩窄任务边界（如限定在结构化环境中运行），要么通过安全壳保险（如用规则系统兜底）。

## 常见冲突类型与解决策略

### 感知与推理的冲突

感知系统输出的是概率性结构化观测（目标检测框+置信度），推理系统通常期望确定性的符号输入。两者之间的粒度不匹配是常见冲突。

**策略：** 不在感知层做硬阈值，而是将置信度传递给推理层。推理层应能处理带不确定性的输入——例如，用贝叶斯推理或加权投票替代确定性推理。如果推理层不支持不确定性输入，则在感知-推理接口处设计一个概率到符号的转换器，但要确保转换器的错误不会导致整个系统失效。

### 生成与验证的冲突

生成系统追求多样性和覆盖度（生成尽可能多的候选），验证系统追求高效搜索（减少需要检查的候选数）。两者的成本结构冲突。

**策略：** 使用两级过滤——第一级用快速便宜的自回归生成+轻量校验过滤明显不合格的输出，第二级用昂贵但精确的验证器深度检查剩余候选。LightMUN、AlphaCode 和 Self-Refine 都采用了类似的结构。

### 规划与控制的冲突

规划器工作在大时间尺度（秒-分钟），控制器工作在小时间尺度（毫秒-秒）。规划器的优化目标（全局最优、高回报）与控制器的优化目标（局部稳定、平滑执行）可能存在冲突。

**策略：** 在规划器和控制器之间引入目标转换器——将规划的长期回报目标转化为控制器可以跟踪的参考轨迹、设定点和约束边界。现代 MPC 框架天然支持这种分层设计。

### 科学发现与实际"好用"的冲突

科学发现任务要求探索和开放性——好系统产生意料之外的新假设。实际工程任务要求稳健和可复现——好系统在相同输入下输出相同的合理结果。同一系统同时满足两者极为困难。

**策略：** 将探索策略与执行策略分离。在探索阶段，使用最大化信息增益或发现新奇性的策略生成候选。在执行阶段，使用已验证的稳健策略完成生产任务。两者之间的转换需要明确的安全门（gate）机制。

## 如何文档化问题空间复合

建议在工程文档中使用如下格式描述问题空间复合：

```markdown
## 问题空间分析
- 主问题空间：规划、控制与序列决策
- 副问题空间：
  - 感知（3D 目标检测 → 跟踪）
  - 推理（交通语义理解）
  - 执行（底层控制接口）
- 复合模式：混合式（感知+推理紧耦合 Transformer，控制作为独立环路）
- 瓶颈环节：感知 → 规划的接口（检测延迟每增加 100ms 导致规划成功率下降 15%）
- 冲突处理：感知输出传递全置信度分布而非硬检测框
```
