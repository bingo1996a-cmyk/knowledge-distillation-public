# 跨问题空间的评估指标体系

## 定位

不同问题空间要求不同的评估方法。分类任务的准确率在控制任务中毫无意义，生成任务的 FID 在推理任务中不适用。本页系统梳理各问题空间的核心评估维度、代表指标及其适用边界。

## 评估的通用维度

所有问题空间的评估都可以从以下五个维度分析：

| 维度 | 问题 | 典型方法 |
|------|------|---------|
| 准确度 | 输出是否正确 | 错误率、编辑距离、通过率 |
| 鲁棒性 | 对输入扰动是否稳定 | 对抗测试、分布外测试、随机种子稳定性 |
| 效率 | 达到结果需要多少资源 | 推理时间、样本复杂度、计算成本 |
| 安全性 | 输出是否造成损害 | 违规率、拒绝率、审计通过率 |
| 可解释性 | 能否理解决策过程 | 归因分数、推理链一致性、反事实解释 |

## 感知问题空间的评估

### 核心问题
"系统对世界的观测与真实世界状态在多大程度上一致。"

### 代表性指标

| 子任务 | 指标 | 说明 |
|--------|------|------|
| 目标检测 | mAP（mean Average Precision） | 在 IoU 阈值（0.5-0.95）上对精确率-召回率曲线积分 |
| 语义分割 | mIoU（mean Intersection over Union） | 每类的预测区域与标注区域的交并比 |
| 深度估计 | RMSE, AbsRel, delta1/delta2 | 预测深度与真实深度的绝对误差和相对误差 |
| 姿态估计 | ADD-S, ADD-S AUC | 预测姿态与真实姿态下的平均 3D 点距离 |
| 视频理解 | Top-K accuracy, mean per-class accuracy | 动作分类的 accuracy 和平衡准确率 |
| SLAM | ATE（Absolute Trajectory Error）, RPE（Relative Pose Error） | 估计轨迹与真实轨迹的全局对齐误差和局部偏移误差 |

**注意事项：** 感知评估极易受到标注偏差和分布偏移的影响。mAP 在 COCO 上的高分不能保证在自动驾驶数据集上同样有效。建议始终同时报告在至少两个不同数据集上的表现，并且包含 OOD（Out-of-Distribution）检测性能——这是感知系统安全评估中最常被忽略但最重要的维度。

## 生成问题空间的评估

### 核心问题
"生成的样本在统计质量和语义正确性上是否接近真实分布。"

### 代表性指标

| 子任务 | 指标 | 说明 |
|--------|------|------|
| 图像生成 | FID（Fréchet Inception Distance） | 真实和生成图像在 Inception 嵌入空间的分布距离 |
| 图像生成 | IS（Inception Score） | 生成图像的类别可区分性和多样性 |
| 文本生成 | Perplexity, BLEU, ROUGE, METEOR | 语言模型概率、n-gram 重叠、最长公共子序列 |
| 文本生成 | Human preference score (ChatGPT/Claude 评分) | 大模型作为人类偏好的代理评估者 |
| 代码生成 | pass@k | 在 k 个候选中有至少一个通过测试的概率 |
| 分子生成 | Validity, Uniqueness, Novelty | 分子有效/独特/新颖的比例 |
| 图像-文本对齐 | CLIP Score, PickScore | 图像和文本在对比学习空间中的余弦相似度 |

**注意事项：** 生成评估面临的核心困难是自动指标与人类判断之间的差距。FID 对模式覆盖和人为伪影敏感但不反映语义正确性；BLEU 和 ROUGE 偏重 n-gram 重叠而非语义等价；Human preference score 虽然更符合直觉但引入代理模型的偏差。推荐始终同时使用至少一种自动化指标和一种人类评估（人工抽样或 LLM-as-judge）。

## 推理问题空间的评估

### 核心问题
"推理结果的正确性和推理过程的合理性。"

### 代表性指标

| 子任务 | 指标 | 说明 |
|--------|------|------|
| 数学推理 | accuracy, pass@k（MATH, GSM8K） | 答案正确率 |
| 逻辑推理 | FOL entailment accuracy, AR-LSAT | 逻辑蕴含判断和 LSAT 分析推理 |
| 知识推理 | Hits@k, MRR（KG 上的链接预测） | 知识图谱中预测关系的排名 |
| 规划 | Plan length, success rate, regret | 规划的解质量、成功率和累积后悔 |
| 程序验证 | 验证通过率, 反例次数 | 验证器确认正确的程序比例 |
| 多步推理 | step validity, chain consistency | 推理链中每一步是否合理，链是否自洽 |

**注意事项：** 推理评估最容易被"捷径学习"欺骗——模型可能通过模式记忆（如将"为什么 X"映射到记忆中类似的问题-答案对）而非真正的推理来回答问题。建议使用分布外测试集（例如 MATH 中检查 OOD 子集）和对抗性扰动（改变问题表述但保持逻辑结构不变）来鉴定模型的真实推理能力。

## 规划与控制问题空间的评估

### 核心问题
"策略在动态环境中能否稳健地达成目标。"

### 代表性指标

| 子任务 | 指标 | 说明 |
|--------|------|------|
| 强化学习 | Cumulative return, episode length | 累积奖励和任务持续时间 |
| 控制 | RMSE tracking error, settling time | 轨迹跟踪误差和收敛时间 |
| 安全 | Constraint violation rate, safety cost | 约束违规频率和严重程度 |
| 鲁棒性 | Reward under disturbance, worst-case return | 对抗扰动下的性能和最坏情况表现 |
| 样本效率 | Sample complexity, reward per environment step | 达到特定性能所需的交互步数 |
| 仿真到现实 | Sim-to-real gap, zero-shot transfer rate | 在仿真中训练的策略在真实系统中的表现差距 |

**核心方法论**：离线指标与在线指标之间的鸿沟是规划与控制领域最严重的问题之一。在离线评估中表现优异的策略在上线后常常因为分布漂移而性能骤降。因此，规划与控制任务的核心评估原则是：**以在线闭环评估为主，离线指标只能作为筛选器使用。**

## 科学发现与闭环优化问题空间的评估

### 核心问题
"系统能否在低成本条件下高效发现新知识或新设计。"

### 代表性指标

| 子任务 | 指标 | 说明 |
|--------|------|------|
| 实验设计 | Query efficiency, regret in Bayesian optimization | 找到最优解所需的实验次数 |
| 假设发现 | Novelty ratio, hypothesis acceptance rate | 新假设中最终被实验验证的比例 |
| 闭环优化 | Cumulative benefit, time-to-solution | 优化过程中累计收益和收敛时间 |
| 代理模型 | R², log-likelihood on held-out experiments | 代理模型对未观测实验的预测能力 |
| 科学自动 | Synthetic yield, accuracy of AI-generated protocols | AI 生成的实验方案在实际实验中的成功率 |

**注意事项：** 科学发现评估的独特困难在于反馈延迟——在自动实验系统中，一轮实验可能耗时数小时到数天，评估一个闭环策略的效果需要运行多个完整闭环周期。离线模拟在此场景中不可或缺但必须小心仿真误差对评估结果的影响。

## 跨空间比较的困难

不同问题空间的指标在数值上不可比较。mAP 0.75 和 pass@k 0.6 之间没有直接关系，不能用于判断"哪个问题空间更难"。当需要在项目层面比较不同方法时，建议使用**归一化评分矩阵**：对每个任务选取一个基准方法，将所有指标归一化为相对于基准的得分（baseline-normalized score），然后按维度（准确度、鲁棒性、效率、安全性）汇总。这种方法虽然粗粒度，但至少支持跨空间的结果沟通。
