# 运行时治理（Runtime Governance）、策略执行与安全降级

## 定位

训练后治理并不能代替运行时治理。runtime governance 关注的是：当模型已经在真实环境中运行时，系统如何执行策略、如何发现越界、如何触发降级、如何把失败限制在可控边界内。

## 一、为什么运行时治理不可省略

- 模型可能在部署环境遇到训练时未覆盖的输入；
- tool use 与外部系统调用会引入新的风险面；
- 多步骤 agent 在长期执行中会发生目标漂移；
- 高风险场景要求“失败可控”，而不只是平均指标好。

## 二、核心对象

### 1. policy registry

记录当前生效的规则、例外、审批条件和版本信息。

### 2. enforcement point

在实际执行链路中插入检查点，例如：

- 输入过滤；
- 工具调用许可；
- 输出约束检查；
- 风险分级后的人工审批。

### 3. safe degradation

当系统无法维持高性能运行时，不应直接崩溃，而应退化到更保守的可控模式。

## 三、常见降级策略

- 从自动执行退化到建议模式；
- 从开放工具集退化到白名单工具集；
- 从长链任务退化到单步确认；
- 从在线学习退化到冻结策略。

## 四、与事故治理的关系

runtime governance 不是 incident response 的替代，而是 incident prevention 与 damage containment 的前置层。
