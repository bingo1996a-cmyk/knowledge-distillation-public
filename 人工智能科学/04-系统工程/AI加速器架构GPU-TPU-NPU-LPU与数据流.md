# 人工智能加速器架构：GPU、TPU、NPU、LPU 与数据流（Dataflow）

## 这页解决什么问题

大模型训练和推理常被描述成“算法问题”，但当模型真正进入工程实现，瓶颈往往会转移到硬件：算子能否高效映射到芯片、激活和权重在何处存放、片上和片外带宽是否足够、集群内通信能否承受并行策略、推理时 KV 缓存如何摆放。理解人工智能加速器，不是为了记住设备名称，而是为了回答：**什么计算在什么地方发生，数据怎样移动，系统上限由谁决定**。

## 基本思想

衡量加速器不能只看峰值算力（FLOPs），至少还要同时看四件事：

1. **算力密度**：单位时间可完成多少矩阵或张量运算；
2. **存储层次**：寄存器、片上缓存、高带宽显存、主存与外部存储如何协同；
3. **数据流（Dataflow）**：权重、激活和部分和（partial sums）如何在芯片内外移动；
4. **互联与软件栈**：单芯片效率能否在多芯片、多机环境中兑现。

对大模型而言，很多阶段不是算力不够，而是带宽、访存和通信先撞墙。

## 面向一年级读者的直观比喻

可以把芯片理解成“加工厂”，把数据理解成“原材料”。若工厂里的机器很快，但原材料总在路上，机器仍会空转。AI 加速器的核心问题，就是尽量让“算”和“取数”同步，让昂贵计算单元少等待。

## 四类典型加速器

### 1. 图形处理器（Graphics Processing Unit, GPU）

GPU 原本服务图形并行计算，但因其大规模并行向量/矩阵能力、成熟软件生态和可编程性，成为当前训练与推理的主力。GPU 的优势在于：
- 通用性强；
- 编程栈成熟；
- 适合从研究到产业的大规模迁移。

其代价是：
- 功耗较高；
- 通用性带来部分效率损失；
- 大规模集群下通信与调度压力显著。

### 2. 张量处理器（Tensor Processing Unit, TPU）

TPU 更强调张量运算与软件—硬件协同设计。它通常在矩阵乘法、静态图优化和大规模分布式训练中具备优势，适合深度整合的云侧环境。

### 3. 神经处理器（Neural Processing Unit, NPU）

NPU 多用于边缘端、移动端或专用推理设备。它们通常针对低功耗、低时延、定点量化和特定算子做优化，更适合部署而非超大规模预训练。

### 4. 语言处理器（Language Processing Unit, LPU）等推理专用芯片

这一类器件更聚焦大语言模型推理，尤其是 token 级低时延解码、流水调度和缓存复用。其优势往往体现在交互式推理延迟，而不是训练通用性。

## 数据流视角：为什么它比器件名称更重要

同一矩阵乘法在不同数据流设计下，性能和能耗可差很多。常见思路包括：
- **weight stationary**：尽量让权重留在片上，输入不断流过；
- **output stationary**：尽量让部分和留在片上，减少回写；
- **activation stationary**：优先保持激活不频繁搬运。

大模型训练和推理其实都在不断做类似权衡：
- 是把更多数据留在片上，还是换取更灵活调度；
- 是增加算子融合，还是牺牲可维护性；
- 是压缩参数，还是转移负担到反量化与缓存管理。

## 对训练系统的影响

### 1. 并行策略受硬件约束

数据并行、张量并行、流水并行、专家并行（expert parallelism）并不是纯算法问题。能否这样并，取决于：
- 显存容量是否足够；
- 节点内互联是否足够快；
- 梯度聚合与参数交换能否承受。

### 2. 训练效率常由带宽与通信决定

算子理论复杂度相同，并不代表实际吞吐相同。大批量训练经常被以下因素限制：
- 参数与优化器状态过大；
- 激活重算与显存换时间策略；
- 跨设备 All-Reduce 与 All-to-All 通信；
- 数据输入流水线供给不足。

## 对推理系统的影响

### 1. 自回归解码偏“内存受限”

大语言模型推理中的一个典型现象是：单个 token 解码往往不是纯算力瓶颈，而是 KV 缓存读取、访存模式和调度开销占主导。

### 2. 量化与缓存布局强依赖硬件

相同量化位宽在不同设备上的收益不同。原因是硬件对低比特算子、张量核心、缓存对齐和反量化路径支持不一样。

### 3. 端侧与云侧设计目标不同

端侧更重视功耗、内存占用、时延上界和鲁棒降级；云侧更重视吞吐、租户隔离、资源复用和弹性伸缩。

## 典型工程约束

- 不能只按“峰值 TFLOPs”选设备；
- 训练与推理最优硬件未必相同；
- 单卡最优不等于集群最优；
- 采购、维护、能耗、机柜、电力和散热是系统成本的一部分。

## 常见误区

- 把芯片差异简单理解为“谁算力更高”；
- 忽视片上缓存和高带宽显存的重要性；
- 只比较单模型 benchmark，不比较系统级 TCO（总拥有成本）；
- 把硬件选型和并行策略分开考虑。
