## 1. 核心思想

推测解码的目标是：用较小、较快的草稿模型先提出若干 token 候选，再由主模型并行验证，从而减少平均生成时延。

## 2. 基本流程

1. 草稿模型生成多个候选 token；
2. 主模型对候选序列做验证；
3. 若候选被接受，则一次前进多个 token；
4. 若被拒绝，则回退到主模型正常解码。

## 3. 为什么有效

传统自回归解码一次只前进一步。推测解码试图把“多个未来 token 的猜测”提前做掉，从而提高主模型每次前向传播的利用率。

## 4. 关键权衡

### 4.1 草稿模型质量

- 太弱：接受率低，收益有限；
- 太强：草稿模型本身成本过高。

### 4.2 批处理与并发

高并发时，吞吐收益更明显；低并发时，调度开销可能抵消收益。

### 4.3 时延与吞吐并不总一致

有些配置能提高整体吞吐，但单请求尾时延未必改善。

## 5. 与 KV Cache 的关系

推测解码与 KV Cache 管理密切相关，因为候选 token 的验证会影响缓存复用与回滚逻辑。
