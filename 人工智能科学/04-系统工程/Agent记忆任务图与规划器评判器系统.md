# 智能体记忆、任务图与 planner-critic 系统

## 定位

当大模型（large language model, LLM）从“一次性回答器”变成“持续交互系统”后，问题就不再只是生成下一段文本，而是：

- 如何在多轮、多任务、多工具环境下保存状态；
- 如何把目标拆成可执行子任务；
- 如何在执行中自检、回滚、纠错；
- 如何在高风险场景中留下可审计轨迹。

这篇笔记讨论的不是单个模型，而是 agent operating substrate，即智能体运行基座。

## 一、概念边界

### 1. 记忆不等于向量数据库

记忆（memory）至少包含四类：

1. **工作记忆**：当前回合上下文、活跃约束、当前计划。
2. **情节记忆**：历史交互、失败案例、已执行动作、环境反馈。
3. **语义记忆**：稳定知识、规则、文档、实体关系。
4. **程序性记忆**：工具调用模板、策略壳、工作流习惯。

向量数据库通常只覆盖其中一部分，主要用于语义检索。

### 2. 任务图不等于提示词链

任务图（task graph）强调：

- 节点是子任务、工具操作、审批动作或验证动作；
- 边表示依赖、前置条件、数据流、控制流或失败回退关系；
- 图通常不是简单线性链，而更接近有向无环图（Directed Acyclic Graph, DAG）或带条件分支的状态机。

### 3. planner-critic 不是“多调用几次模型”

planner 负责提出任务分解、资源配置与执行顺序；critic 负责检查：

- 目标是否偏移；
- 约束是否违反；
- 证据是否不足；
- 工具调用是否越权；
- 当前结果是否达到停止条件。

## 二、系统结构

一个可持续运行的智能体基座通常包含六层。

### 1. 输入与状态层

- 用户目标
- 环境状态
- 工具状态
- 权限状态
- 风险级别

### 2. 记忆层

- 短期上下文缓存
- 长期语义存储
- 交互历史索引
- 失败案例库
- 审计日志索引

### 3. 任务图层

- 任务分解器
- 子任务依赖图
- 优先级与资源预算
- 分支条件与回滚边

### 4. 计划与执行层

- planner 生成计划
- executor 调用工具和外部系统
- monitor 监控执行状态
- critic 对结果、证据和风险进行复核

### 5. 安全壳与审批层

- 权限检查
- guardrails
- 人机审批流
- 高风险动作升级处理

### 6. 审计与学习层

- trace
- 失败样例回流
- 回放与复盘
- 版本比较

## 三、一个最小形式化

设任务图为 \\(G=(V,E)\\)，其中 \\(V\\) 是子任务集合，\\(E\\) 是依赖关系。

智能体在图上生成执行轨迹 \\(\tau=(v_1, v_2, \dots, v_T)\\)，目标可以写为：

$$
\max_{\pi} \; \mathbb{E}_{\tau \sim \pi} \left[ \sum_{t=1}^{T} r_t - \lambda \sum_{t=1}^{T} c_t - \mu \sum_{t=1}^{T} q_t \right]
$$


其中：

- \\(r_t\\)：子任务完成收益；
- \\(c_t\\)：时间、token、API、实验成本等资源代价；
- \\(q_t\\)：风险、越权、证据不足、不可逆操作等惩罚；
- \\(\lambda, \mu\\)：成本与风险权重。

critic 的作用并不是替代 planner，而是定义一个审查算子 \\(C\\)：

$$
C(v_t, s_t, o_t) \rightarrow \{\text{accept},\; \text{revise},\; \text{rollback},\; \text{escalate}\}
$$


其中 \\(s_t\\) 为当前状态，\\(o_t\\) 为执行结果。

## 四、记忆设计要点

### 1. 记忆要有生命周期管理

不是所有历史都应永久保留。需要区分：

- 会话级缓存
- 项目级记忆
- 长期知识库
- 审计留档

### 2. 记忆要保存来源与置信信息

记忆条目至少应保存：

- 写入时间
- 来源
- 写入原因
- 适用范围
- 置信等级
- 是否可覆盖

### 3. 记忆写入本身是一个受控动作

若把错误中间结论写入长期记忆，会形成“错误固化”。

因此长期记忆写入应经过：

- 证据检查
- 冲突检查
- 去重与版本化
- 必要时人工批准

## 五、任务图设计要点

### 1. 节点类型应区分

常见节点可分为：

- reasoning node：内部推理或计划更新
- tool node：工具执行
- retrieval node：检索
- approval node：人工审批
- verification node：校验
- rollback node：回滚

### 2. 图上必须显式表达失败路径

很多 agent 失败不是因为不会走主路径，而是失败后没有安全退出机制。

因此任务图里要显式写出：

- 重试条件
- 最大重试次数
- 回滚点
- 人工接管点
- 中止条件

### 3. 图不应与模型内部思维完全耦合

任务图是系统级控制对象，目标是：

- 可解释
- 可审计
- 可回放
- 可做权限控制

而不是暴露所有内部草稿。

## 六、planner-critic 的几种常见工作模式

### 1. 先规划后执行

适合：

- 任务结构稳定
- 资源预算明确
- 风险较高

### 2. 逐步规划、逐步复核

适合：

- 环境反馈强
- 工具调用不确定
- 长时任务

### 3. 双层 planner

- 高层 planner 负责任务图与资源预算
- 低层 planner 负责单步操作和工具参数

这在 scientific agent、软件工程 agent、多智能体编排中尤其常见。

## 七、执行回滚与异常恢复

### 1. 为什么必须回滚

因为 agent 常常会面对：

- 工具调用失败
- 检索证据冲突
- 环境状态改变
- 权限被拒绝
- 高风险动作误触发

### 2. 回滚对象不只是数据

还包括：

- 状态回滚
- 计划回滚
- 权限状态恢复
- 下游副作用补偿

### 3. 回滚策略

- 软回滚：撤销当前步骤，保留上下文
- 硬回滚：恢复到检查点
- 补偿事务：对不可逆操作做后置补偿
- 人工接管：回滚后交由人类审批

## 八、典型失败模式

### 1. 伪记忆膨胀

系统把大量无关内容写入长期记忆，导致召回污染。

### 2. 任务图退化为线性链

表面看似 workflow，实际上不能处理条件分支、异常与审批。

### 3. critic 与 planner 目标不一致

planner 优先完成任务，critic 优先避免风险，两者没有统一目标函数时容易彼此抵消。

### 4. 无来源记忆污染

模型把未经证实的中间结论存入长期库，后续又被当成事实反复使用。

### 5. 回滚缺失

系统只能前进，不能安全撤回，导致一次错误扩散成系统级事故。

## 九、评测指标

应至少从以下维度评测：

- 任务完成率
- 长时成功率
- 平均重规划次数
- 失败后恢复率
- 回滚成功率
- 长期记忆污染率
- 证据引用准确率
- 人工接管率
- 单任务总成本
- trace 完整性

## 十、研究切口

1. **记忆写入策略学习**：何时写入、写入什么、何时遗忘。
2. **任务图自动构建**：从自然语言目标、文档或历史轨迹中抽取 task graph。
3. **planner-critic 协同优化**：把正确性、成本、风险写成显式多目标。
4. **回滚与补偿机制**：把事务处理思想引入 agent 系统。
5. **面向 scientific agent 的实验状态记忆**：把实验条件、结果与因果解释连到同一图结构里。
6. **面向高风险系统的审批图**：把 human approval 作为一等节点纳入执行图。
