# 优化器状态切分、内存带宽与规模化训练

## 1. 为什么训练大模型会被“状态”卡住

模型参数并不是训练显存的唯一来源。实际训练时，至少要存：

- 参数；
- 梯度；
- 优化器状态；
- 激活；
- 通信缓冲区。

以 Adam 为例，通常需要为每个参数额外维护一阶矩与二阶矩，因此优化器状态开销很大。

## 2. 内存主要消耗在哪里

训练显存通常可粗略分为：

1. 参数
2. 梯度
3. optimizer state
4. activation
5. temporary buffer

在大模型训练中，真正限制扩展的往往不是 FLOPs，而是：

- HBM 容量；
- HBM 带宽；
- 节点间通信；
- optimizer state 的冗余复制。

## 3. ZeRO 与状态切分

ZeRO（Zero Redundancy Optimizer）的核心思想是：

- 不再让每个数据并行副本都保存全量 optimizer state、梯度和参数副本；
- 而是把这些状态切分到不同设备上。

大致可理解为：

- Stage 1：切 optimizer state
- Stage 2：再切梯度
- Stage 3：进一步切参数

收益：

- 显存占用显著下降；
- 允许训练更大模型。

代价：

- 通信频率上升；
- 调度复杂度增加；
- 带宽变成瓶颈。

## 4. 激活检查点与重计算

如果 activation 存不下，可以只保存部分中间结果，其他在反向传播时重新计算。这就是 activation checkpointing。

本质是：

- 用算力换内存；
- 减少前向中间状态存储；
- 让更大 batch 或更长序列成为可能。

## 5. 数据并行、张量并行、流水并行

规模化训练通常组合三类并行：

- 数据并行（Data Parallelism）
- 张量并行（Tensor Parallelism）
- 流水并行（Pipeline Parallelism）

三者解决的问题不同：

- 数据并行：扩展样本吞吐；
- 张量并行：把单层计算拆到多卡；
- 流水并行：把网络层划分到不同设备。

## 6. 真正的瓶颈：带宽与拓扑

很多规模化训练失败，并不是理论算法不够好，而是：

- NVLink / PCIe / InfiniBand 拓扑不匹配；
- 通信与计算无法重叠；
- all-reduce 成本过高；
- optimizer state 的读写占满内存带宽。

因此，大模型训练本质上同时是一个系统优化问题。
