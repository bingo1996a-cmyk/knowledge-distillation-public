# Checkpointing、重计算与内存—计算权衡（Checkpointing, Recomputation, and Memory–Compute Tradeoffs）

## 1. 为什么这页重要

大模型训练与长上下文推理都受到显存与带宽约束。很多时候，瓶颈不是 FLOPs 不够，而是：

- 激活存不下；
- 优化器状态太大；
- 通信和显存拷贝太慢。

因此，需要系统性地讨论 checkpointing、recompute 与 memory–compute tradeoff。

## 2. 激活检查点（Activation Checkpointing）

训练时，反向传播需要前向阶段的中间激活。最直接做法是全部存储，但显存消耗很大。激活检查点的思路是：

- 只保存部分关键中间结果；
- 其余在反向时重新计算。

这样可以显著降低显存占用，但会增加额外计算。

## 3. 重计算（Recomputation）的基本逻辑

设前向成本为 $C_f$，完整存储激活的显存为 $M$。若只存关键节点，可把显存降到 $M' < M$，代价是反向时多出一部分重算成本 $C_r$。

工程核心问题不是“要不要重算”，而是：

- 重算多少层；
- 在哪里切分；
- 与张量并行、流水并行如何协同。

## 4. 优化器状态与参数分片

除了激活，优化器状态常常同样占大头。Adam 一类优化器需要：

- 参数；
- 梯度；
- 一阶矩；
- 二阶矩。

因此参数分片（sharding）和状态 offload 往往与 checkpointing 配合使用。

## 5. 典型权衡

### 5.1 显存优先

- 更激进的 checkpointing；
- 更频繁的重计算；
- 适合单机资源受限场景。

### 5.2 吞吐优先

- 少重算，多存储；
- 更适合大集群、高带宽场景。

### 5.3 成本优先

- 需要把 GPU 单价、训练时长、能耗一起考虑。

## 6. 与长上下文和推理系统的关系

在推理阶段，虽然不需要反向传播，但长上下文会导致 KV cache 爆炸。这里同样存在 memory–compute tradeoff：

- 是保存更多 cache，还是部分重算；
- 是驻留 GPU，还是分层到 CPU / SSD；
- 是牺牲延迟，还是牺牲吞吐。

## 7. 实践中的常见技术组合

- activation checkpointing + ZeRO/sharding；
- mixed precision + recompute；
- tensor parallel + pipeline parallel + rematerialization；
- KV cache paging + prefix sharing。
