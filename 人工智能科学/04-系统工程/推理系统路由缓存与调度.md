# 推理系统中的路由、缓存与调度

## 定位

这一笔记补在“推理、服务与部署”之后，进一步回答：当系统中不止一个模型、不止一种工具链、不止一种请求长度时，如何在成本、时延、质量之间做工程化最优。

在现代模型服务中，真正决定可用性的往往不是“模型是否最强”，而是：

- 请求该走哪个模型；
- 哪些上下文可以缓存；
- 哪些请求该如何排队与切批；
- 长任务与短任务如何共存；
- 工具调用链路如何避免拖垮 SLA。

## 一、为什么这一层独立成题

大模型应用很容易在实验阶段给人错觉：单机调用一个强模型就能完成任务。

但真实线上环境通常会同时出现：

- 长短上下文混合；
- 高低价值请求混合；
- 实时请求与批处理混合；
- 付费层级或租户优先级差异；
- 工具链路导致的长尾延迟。

因此，系统需要在运行时做三个决策：

1. 路由（routing）
2. 缓存（caching）
3. 调度（scheduling）

## 二、路由是什么

路由是指：根据任务类型、复杂度、时效要求、成本预算和风险等级，决定把请求送到哪一套求解路径。

### 典型路由维度

- 模型大小：大模型 / 小模型
- 模型能力：通用 / 代码 / 多模态 / 推理型
- 执行路径：纯生成 / RAG / 工具调用 / 多智能体编排
- 风险等级：自动执行 / 人工审批 / 拒绝处理
- 时延目标：低延迟优先 / 高质量优先

### 一个抽象例子

可以定义一个选择器：

$$
\pi_{route}(x) \rightarrow m, w
$$


其中：

- \(x\) 是请求特征；
- \(m\) 是模型；
- \(w\) 是工作流或工具链。

目标不是固定选“最强模型”，而是最小化期望代价：

$$
\min \; \mathbb{E}[\alpha C + \beta L - \gamma Q + \delta R]
$$


其中 \(C\) 为成本，\(L\) 为延迟，\(Q\) 为质量，\(R\) 为风险。

## 三、缓存是什么

缓存的本质是把重复计算前移或复用。对模型系统，至少有四类缓存：

### 1. 前缀缓存（prefix caching）

多个请求共享相同系统提示、相同文档前缀或相同历史上下文时复用前缀计算。

### 2. KV cache

自回归解码中复用注意力历史键值，减少重复计算。

### 3. 检索缓存

对高频查询结果、rerank 结果或文档切片结果缓存。

### 4. 结果缓存

对稳定问题直接返回已验证结果，常用于 FAQ、配置解释、标准流程。

## 四、缓存的收益与代价

### 收益

- 降低延迟
- 降低推理成本
- 提高吞吐
- 减少重复检索与重复工具调用

### 代价

- 时效性风险
- 版本错配
- 权限污染
- 结果过期
- 调试复杂度上升

因此，缓存系统不能脱离版本与权限设计。

## 五、调度是什么

调度处理的是“同一时刻很多请求抢同一批资源”的问题。

### 核心挑战

- 请求长度差异大；
- 工具调用会阻塞；
- 长上下文请求占用大量显存；
- 短请求可能被长请求拖慢；
- 多租户环境下需要公平性和优先级。

### 常见目标

- 最大化吞吐
- 控制 P95 / P99 延迟
- 降低 GPU 空转
- 保证高优先级请求先服务
- 防止单类任务垄断资源

## 六、三类典型调度策略

### 1. 批处理调度

把多个请求合并成 batch，提高硬件利用率。

问题在于：长度差异大时，批内最慢请求会拖累其他请求。

### 2. 分层队列调度

按优先级、任务类型、上下文长度分不同队列，避免相互污染。

### 3. 预测式调度

先估计请求长度、工具调用概率、风险级别，再决定排队或路由路径。

这类策略可与学习方法、bandit 或强化学习结合。

## 七、为什么工具调用让问题更难

纯模型生成只需要考虑 token 计算；
带工具的智能体系统则还要考虑：

- 外部 API 延迟不确定；
- 工具失败需要重试；
- 浏览器、代码执行、数据库查询耗时差异大；
- 工具链路中断会让 trace 变长；
- 同一个请求会在“模型计算”和“外部等待”之间反复切换。

因此，agent 调度更像异构作业调度（heterogeneous job scheduling），不是单一推理调度。

## 八、路由、缓存、调度的耦合

三者不能分开孤立优化。

### 例子

- 路由到小模型可能减少计算，但如果失败后触发多次补救，总成本反而更高；
- 激进缓存可能降低延迟，但若缓存了旧索引，会降低事实正确率；
- 单纯追求吞吐的调度可能恶化高价值请求的尾延迟。

因此，实际优化目标往往是多目标的。

## 九、与控制理论的连接

这层问题与控制和运筹方法高度相通：

- 路由可视为离散决策或 mode switching；
- 缓存更新可视为状态管理问题；
- 调度可视为约束下资源分配；
- 多模型系统可视为混合系统（hybrid system）；
- 延迟与失败可视为随机扰动。

从这个角度看，现代 AI serving 其实是一个大规模随机控制与调度问题。

## 十、可研究的数学抽象

### 1. 队列论（queueing theory）

分析到达率、服务率、等待时间分布。

### 2. 多臂老虎机（multi-armed bandit）

在质量未知、成本不同的多个模型间做在线选择。

### 3. 马尔可夫决策过程（Markov decision process, MDP）

将动态路由与调度统一到长期回报优化。

### 4. 鲁棒优化

处理外部工具延迟、失败率与工作负载波动。

## 十一、资源受限条件下的可行最优路径

对于实验室或中小团队，最优路径通常不是设计复杂调度器，而是：

1. 先做静态分流：简单任务走小模型，复杂任务走强模型；
2. 对高频系统提示和高频检索前缀做缓存；
3. 把长上下文任务和普通任务分队列；
4. 保存失败统计，逐步升级为学习式路由。

这是成本最低、收益最明确的工程路径。

## 十二、博士研究切口

1. 多模型混合路由的成本-质量最优控制。
2. 带工具调用的异构作业调度。
3. 面向长上下文推理的缓存一致性设计。
4. 面向 agent workflow 的 tail latency 建模。
5. 将 queueing + RL 用于在线 serving policy 学习。
