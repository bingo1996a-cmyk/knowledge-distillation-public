# 开题报告、论文与系统搭建的映射模板

## 用途

这份模板的目标不是提供固定格式，而是把博士阶段最常见的三类产物对齐起来：

1. 开题或研究计划；
2. 论文或专利；
3. 系统、平台或实验工程。

很多研究推进缓慢，不是因为缺少想法，而是因为这三类产物长期脱节。

## 一、最小映射框架

建议把一个研究题目始终压缩到六个核心对象：

1. **问题（Problem）**
2. **理论对象（Theory）**
3. **模型/算法（Model/Algorithm）**
4. **实验（Experiment）**
5. **系统（System）**
6. **证据（Evidence）**

一个成熟选题应能回答：

- 研究问题是什么；
- 使用哪些理论工具；
- 提出了什么模型或算法；
- 如何设计实验；
- 是否沉淀成系统能力；
- 证据是否足够支撑结论。

## 三、论文结构映射模板

### 1. 摘要

必须对应三件事：

- 问题是什么；
- 方法做了什么；
- 结果证明了什么。

### 2. 引言

建议对应开题报告中的：

- 问题定义；
- 现实意义；
- 差距分析；
- 研究目标。

### 3. 相关工作

按“问题—方法—局限”组织，不按作者流水账组织。

### 4. 理论与模型

这一节应回答：

- 系统建模对象是什么；
- 变量与假设是什么；
- 目标函数或状态转移如何写；
- 你的方法在哪个环节引入新结构。

### 5. 算法或系统实现

需要把理论对象落地到：

- 算法流程；
- 模块结构；
- 训练/求解过程；
- 复杂度与部署要求。

### 6. 实验设计

建议固定回答六个问题：

1. 为什么选这个环境；
2. 基线是否合理；
3. 指标是否对应研究目标；
4. 参数设置是否公平；
5. 是否有消融；
6. 是否有失败分析。

### 7. 结果分析

不要只报表格，应分别分析：

- 主结果；
- 边界条件；
- 失败案例；
- 复杂度与代价；
- 工程可行性。

### 8. 结论与局限

要明确：

- 证据支持到哪一层；
- 哪些结论仍需验证；
- 下一步最自然的扩展是什么。

## 四、系统搭建映射模板

### 1. 模块清单

- 环境模块
- 数据模块
- 模型模块
- 训练模块
- 评测模块
- 日志与审计模块
- 可视化模块

### 2. 实验资产清单

- 配置文件
- 数据版本
- 脚本入口
- 模型权重
- 图表生成脚本
- 结果目录规范
- 失败日志规范

### 3. 复现要求

至少固定：

- 随机种子；
- 环境依赖；
- 运行命令；
- 输出格式；
- 主要图表可自动生成。

## 五、把“理论—模型—实验—系统”连起来

建议用下表做选题审查：

| 层次 | 关键问题 | 当前是否清楚 | 证据形态 |
|---|---|---:|---|
| 理论 | 问题是否被形式化 |  | 公式、定义、命题 |
| 模型 | 方法是否有明确结构 |  | 模块图、算法 |
| 实验 | 是否有可执行验证方案 |  | 指标、基线、消融 |
| 系统 | 是否能形成稳定工程资产 |  | 代码、配置、日志 |
| 结论 | 证据是否足以支撑主张 |  | 图表、统计、案例 |

## 六、适合博士阶段的工作包拆分

### 工作包 A：问题与理论

输出：

- 问题定义文档；
- 形式化符号表；
- 相关理论推导；
- 命题或假设列表。

### 工作包 B：模型与算法

输出：

- 模型结构图；
- 算法流程；
- 伪代码；
- 复杂度分析。

### 工作包 C：实验组织

输出：

- 实验矩阵；
- 对比基线清单；
- 指标定义；
- 结果记录规范。

### 工作包 D：系统沉淀

输出：

- 代码目录规范；
- 配置模板；
- 日志模板；
- 图表生成脚本；
- handoff 文档。

## 七、常见断裂点

### 1. 理论与实验脱节

公式很好看，但实验指标并不验证核心主张。

### 2. 算法与系统脱节

论文方法无法在现有工程框架中稳定运行。

### 3. 系统与论文脱节

代码很多，但无法反推出论文结论来自哪组实验。

### 4. 开题与后续实际研究脱节

开题目标写得很大，但没有分阶段工作包和可交付物。

## 八、对你的主线尤其有用的地方

对于多智能体、强化学习、任务规划、效能评估与控制系统研究，这个模板最有价值的作用是：

- 把状态机、RL、评测指标和系统实现放到同一张图里；
- 区分“理论贡献”“算法贡献”“系统贡献”；
- 在项目推进时保留可审计的研究资产链。

## 九、结论

一份好的博士研究计划，不只是“题目 + 想法”，而是能把：

- 问题定义；
- 理论结构；
- 模型方法；
- 实验设计；
- 系统实现；
- 结论证据

映射成同一套可推进、可核查、可复用的工作流。
