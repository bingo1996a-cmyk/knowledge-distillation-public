# 取证日志模板与再验证清单

## 1. 文档用途

本页给出高风险 AI 系统在事件响应后用于证据保全、复盘和再验证的最小工件模板。它不讨论法律意见，而讨论研究与工程团队如何把 incident handling 压到可执行对象层。

## 2. 取证日志最小字段

### 2.1 事件基本信息

- incident_id
- 首次发现时间
- 发现渠道
- 严重性等级
- 当前状态
- 负责人

### 2.2 系统上下文

- system_id / model_id / model_version
- deployment region / environment
- toolchain version
- policy version
- monitoring ruleset version

### 2.3 关键输入输出

- 触发输入摘要
- 原始输入存储位置
- 关键中间状态引用
- 最终输出摘要
- 人工修正记录

### 2.4 执行轨迹

- tool call 序列
- approval event 序列
- guardrail hit 记录
- route / cache / fallback 记录
- timestamped trace pointer

### 2.5 环境与依赖

- 数据源版本
- 外部 API 状态
- 依赖服务健康度
- 设备/传感器/仪器状态

## 3. 证据保全原则

- 原始日志与派生摘要分离保存；
- 保留哈希、时间戳与版本号；
- 不允许复盘时覆盖原始证据；
- 对高风险事件保留输入、输出、中间轨迹与审批记录的关联指针。

## 4. 再验证清单

### 4.1 问题复现

- 是否能复现实验条件；
- 是否能在沙箱环境重放；
- 是否能定位到触发阈值或失效链路。

### 4.2 根因分析

- 是模型问题、数据问题、工具问题还是策略问题；
- 是否与分布漂移相关；
- 是否与审批流绕过相关；
- 是否与监控规则失配相关。

### 4.3 修复验证

- 修复是否只覆盖表层症状；
- 是否影响其他任务；
- 是否需要回归测试、红队测试与现场再验证；
- 是否需要更新 model card / system card / release gate。

### 4.4 发布门禁

- 再验证是否通过；
- 是否需要分阶段恢复；
- 是否需要额外人工监督；
- 是否需要更新应急预案与培训材料。

## 5. 推荐流程

`incident -> triage -> evidence freeze -> replay -> root cause -> mitigation -> re-verification -> release decision -> monitoring tightening`
