# V39 Structure Index — 工具化

## 1. 总体说明

V39 是 V37—V40 远景路线的第三阶段"工具化"，目标是为知识库搭建可搜索的静态站点（mkdocs + mkdocs-material）并建立持续集成管道。V39 依赖 V38 完成（全局 YAML 元数据为 mkdocs tags 插件提供数据源）。V39 产出物可直接供用户浏览和检索，也为 V40（图谱化）提供了可视化基础。

## 2. 工作分解

### V39.1 — mkdocs 配置 + 主题定制

| 文件 | 说明 |
|------|------|
| `mkdocs.yml` | mkdocs 主配置（docs_dir: docs/，material 主题，完整 nav 结构，搜索/标签插件） |
| `docs/stylesheets/extra.css` | 自定义样式（indigo 主题色、表格/代码块/引用块/导航增强） |
| `docs/V39-structure-index.md` | 本文件 |

配置要点：
- `docs_dir: docs/`：将所有内容文件纳入 `docs/` 子目录，避免与 mkdocs.yml 同目录冲突
- `site_dir: site/`：构建输出到根目录的 `site/` 文件夹
- `exclude_docs`：排除 `log/`、`99-handoff/`、`scripts/`、`superpowers/`、`metadata-baseline.md`、`metadata-index.json` 等非内容文件
- 插件：`search`（支持中英双语索引）、`tags`（标签索引）
- nav 配置覆盖知识库全部 15 个层的入口及主要页面

### V39.2 — 搜索测试 + 导航调优

- **搜索功能验证**：mkdocs-material 的 search 插件配置为支持中文（zh）和英文（en）索引，可全文检索知识库内容
- **导航完整性**：nav 配置包含全部 13 个层（00-overview 至 90-appendices）的入口及主要页面，以及版本索引（V31-V38 结构目录）
- **已知状态**：
  - 部分文件（metadata-baseline.md、各层 README.md 等）未在 nav 中，由 mkdocs 自动发现
  - 23 个内容文件内部断链（指向已重命名或删除的页面），列为已知技术债，`mkdocs build --strict` 会报告但不中断构建

### V39.3 — CI 管道搭建

| 文件 | 说明 |
|------|------|
| `.github/workflows/deploy-mkdocs.yml` | GitHub Actions 工作流：推送到 main 分支时自动构建、质量门禁、部署到 GitHub Pages |
| `docs/scripts/file-spec-check.py` | 文件规范检查脚本（命名规范、大小阈值、存根检测） |

流程（build job）：
1. 检出代码（含 docs/ 子目录）
2. 安装 Python 3.11 + mkdocs + mkdocs-material
3. 执行 `mkdocs build`（主构建，通过后方可部署）
4. 执行 `mkdocs build --strict` 作为链接质量门禁（非阻塞性报告，持续暴露残留断链）
5. 运行 `python scripts/metadata-check.py all` 验证 YAML 元数据完整性（阻塞性）
6. 运行 `python scripts/file-spec-check.py` 检查文件规范合规（阻塞性）
7. 通过 `actions/upload-pages-artifact@v3` 上传到 `site/` 目录

部署流程：
1. `actions/deploy-pages@v4` 部署到 GitHub Pages 环境

**当前质量门禁状态**（2026-05-08）：
- `mkdocs build`：通过
- `mkdocs build --strict`：23 个断链警告（全部为内容文件内部链接，非 nav 问题），列为已知技术债
- YAML 元数据检查：307/307 文件 100% 通过（`tags-index.md` 为 mkdocs 自动生成，已豁免）
- 文件规范检查：308 文件全部通过
- nav 引用：54 个死引用已清理，目前零 nav 警告
