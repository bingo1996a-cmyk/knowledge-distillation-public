# 蒸馏、量化、剪枝与高效适配

## 1. 为什么需要参数高效与推理高效

大模型的主要瓶颈并不只在“能不能训练”，还在：

- 能否放进显存；
- 能否低成本部署；
- 能否快速适配新任务；
- 能否在边缘设备或高吞吐服务上运行。

这就引出四类核心技术：

1. 知识蒸馏（Knowledge Distillation）
2. 量化（Quantization）
3. 剪枝（Pruning）
4. 高效适配（Efficient Adaptation）

## 2. 蒸馏：把大模型的行为迁移到小模型

蒸馏的关键思想是：

> 学生模型不仅学真实标签，还学习教师模型的软输出、隐藏表示或中间关系。

典型蒸馏损失可写为：

$$
\mathcal{L}= (1-\alpha)\mathcal{L}_{task} + \alpha T^2 \mathrm{KL}(p_T^{teacher}\,\|\,p_T^{student}).
$$

其中 $T$ 为温度，$\alpha$ 控制任务损失与蒸馏损失权重。

## 3. 量化：降低数值精度换取吞吐与内存

量化的核心是把高精度浮点表示压到更低比特宽度，例如：

- FP16 / BF16
- INT8
- INT4
- 更低比特权重近似

收益：

- 显存占用下降；
- 带宽压力减小；
- 推理速度可能提升。

代价：

- 可能损害精度；
- 对异常值（outliers）更敏感；
- 不同层对量化误差容忍度不同。

## 4. 剪枝：去掉不重要参数或结构

剪枝可分为：

- 非结构化剪枝：删单个权重；
- 结构化剪枝：删通道、头、层、块；
- 动态稀疏：训练中持续更新稀疏结构。

其关键问题不是“删得越多越好”，而是：

- 硬件是否真的能利用稀疏；
- 被删掉的是冗余还是关键路径；
- 压缩后是否仍可恢复性能。

## 5. 高效适配：少改参数完成迁移

代表方法包括：

- Adapter
- LoRA
- Prefix / Prompt Tuning
- QLoRA

它们的共同目标是：

- 尽量冻结主模型；
- 只训练小规模增量参数；
- 减少显存与训练成本；
- 让同一基座承载多任务适配。

## 6. 四类技术之间的关系

- 蒸馏：偏向“压缩知识”；
- 量化：偏向“压缩数值表示”；
- 剪枝：偏向“压缩结构”；
- 高效适配：偏向“压缩任务迁移成本”。

在真实系统中，它们常常组合使用。

## 7. 与 serving 的关系

这些方法会直接影响：

- KV cache 压力；
- batch size；
- 多租户部署成本；
- 延迟与吞吐；
- 边缘部署可行性。
