# 尺度律、架构权衡与涌现能力

## 定位

这一页讨论现代大模型与基础模型研究中的三个核心主题：

1. **尺度律（scaling laws）**：能力和损失如何随模型、数据、计算扩展而变化；
2. **架构权衡（architectural trade-offs）**：模型结构如何影响训练效率、推理成本与迁移能力；
3. **涌现能力（emergent capabilities）**：能力跃迁到底是统计连续谱、阈值现象，还是评测构造的产物。

## 一、概念边界

尺度律通常是经验规律，而不是普适物理定律。它们回答的是：

- 在给定数据与算力约束下，继续加参数是否值得；
- 什么时候应该优先补数据而不是补模型；
- 训练是否已经接近 compute-optimal 区域。

架构权衡讨论的不是“哪种架构绝对最好”，而是不同任务和系统目标下：

- Transformer、state-space model、Mixture-of-Experts、检索增强模型、稀疏模型等如何交换计算、延迟、记忆与能力；
- 长上下文、流式处理、端侧部署、多模态接口如何重新塑造架构选择。

“涌现能力”则更需要谨慎处理。很多所谓涌现，可能由：

- 任务阈值效应；
- 度量离散化；
- benchmark 设计；
- few-shot prompt 构造；
- 评测噪声

共同造成。

## 二、尺度律主线

### 1. 经验尺度律的基本形式

常见表达是把损失写成模型规模 \(N\)、数据规模 \(D\)、计算 \(C\) 的函数：

\[
L(N,D,C) \approx A N^{-\alpha} + B D^{-\beta} + E C^{-\gamma} + L_\infty
\]

这类形式不是要给出精确自然常数，而是帮助工程决策：

- 模型加大后是否仍有明显收益；
- 数据是否成为瓶颈；
- 训练 token 是否已经足够；
- 后训练是否比继续预训练更划算。

### 2. compute-optimal 视角

工程上更重要的是“给定固定训练预算，怎样分配模型与数据更优”。  
这催生出两类常见判断：

- **参数过大、数据不足**：模型难以充分利用容量；
- **数据过多、模型不足**：学习效率下降，能力上限受限。

### 3. 尺度扩展的隐含条件

尺度律只有在一系列条件近似保持时才有意义，例如：

- 数据分布相对一致；
- 训练目标未发生本质变化；
- 优化器和并行策略足够稳定；
- 架构变化没有打破可比性。

因此，把不同实验环境中的损失曲线直接拼接成“尺度定律”是常见误区。

## 三、架构权衡主线

### 1. 密集模型与稀疏模型

密集模型（dense model）参数全部参与计算，结构简单、训练稳定；  
稀疏模型如 Mixture-of-Experts（MoE）则通过路由降低单位 token 激活成本，但会引入：

- 负载均衡问题；
- 路由噪声；
- 并行与通信复杂度；
- 一致性与部署难度。

### 2. 注意力与长序列处理

标准自注意力（self-attention）在长序列下计算和显存代价高，因此出现了：

- 线性注意力；
- 稀疏注意力；
- segment / chunk 处理；
- memory tokens；
- state-space / recurrent 替代结构。

这里的关键不是“谁替代谁”，而是：

- 长上下文需要的是真正可用的信息保留，还是形式上的 token 长度；
- 系统目标是离线高质量推理，还是低时延在线处理；
- 模型是否需要跨模态/跨轮次记忆。

### 3. 架构选择与任务类型

- 感知任务通常更关心局部归纳偏置与空间结构；
- 语言任务更依赖长程依赖、知识吸收与生成稳定性；
- 控制与具身任务更关心动作表示、低时延与闭环鲁棒性；
- scientific agent 更关心工具接口、可验证性与协议兼容。

## 四、涌现能力主线

### 1. “涌现”现象为什么有争议

一些能力在小模型上几乎为零，大模型上突然出现，看上去像相变。  
但更细看时可能发现：

- 度量是二值的，而底层能力连续变化；
- prompt 设计对结果影响很大；
- 数据覆盖在大模型上跨过了某个任务门槛；
- 后训练或 test-time compute 才是真正能力来源。

### 2. 更稳妥的表述

与其把很多现象都称为“涌现”，不如区分：

- **连续改进（continuous improvement）**
- **阈值效应（threshold effect）**
- **组合能力（compositional capability）**
- **系统增益（system-level gain）**

这对研究设计更有帮助。

## 五、系统工程视角

尺度律、架构与能力，并不是只在预训练阶段决定的。真实系统中至少还受下列因素影响：

- 数据去重与数据配方；
- curriculum 与 mixture 设计；
- 后训练目标；
- 工具调用与检索；
- verifier / search / adaptive compute；
- 部署预算与端侧约束。

因此，同一基础模型在不同系统包裹下会表现出截然不同的“能力边界”。

## 六、常见失败模式

- 只比较参数量，不比较训练 token、数据质量与 compute；
- 把 benchmark 跳变误判为通用能力跃迁；
- 忽视架构对服务成本、延迟和失效恢复的影响；
- 用预训练损失替代全部下游质量判断；
- 只看平均指标，不看尾部风险、校准和 worst-case failure。

## 七、评测指标

### 1. 训练与扩展

- training loss / validation loss；
- compute-normalized performance；
- token efficiency；
- data efficiency；
- convergence stability。

### 2. 架构效率

- 参数利用率；
- activated parameters；
- latency；
- memory footprint；
- throughput / cost。

### 3. 能力与风险

- 下游任务迁移能力；
- reasoning / tool use / long-context 表现；
- calibration；
- failure recovery；
- 部署稳定性。

## 八、研究切口

- scaling law 在多模态、自监督、world model 场景下是否仍稳定；
- 架构创新究竟改变了“渐近上限”还是“工程常数”；
- 涨参数与涨 test-time compute 的边际收益如何比较；
- emergent capability 如何设计更稳健的测量与解释框架；
- 端侧、具身和高风险系统是否需要不同的架构最优点。
