# 持续交互智能体与世界建模

## 定位

这篇笔记讨论的不是“会聊天的代理”，而是能够在持续交互环境中维持状态、形成内部环境表征、调用工具、执行行动并根据反馈更新策略的持续交互智能体（continual interactive agent）。

它位于三个研究方向的交叉处：

- 世界模型（world model）
- 智能体系统（agent system）
- 序列决策与闭环控制（sequential decision-making and closed-loop control）

## 一、概念边界

### 1. 什么是“持续交互”

持续交互不是单轮问答，也不是一次性任务求解，而是系统在较长时域内反复经历：

1. 观测环境；
2. 维护内部状态；
3. 规划下一步动作；
4. 执行动作；
5. 接收反馈；
6. 修改记忆、策略或目标分解。

因此，持续交互智能体的核心不是“回答得像不像人”，而是“在长时闭环中是否保持任务一致性与行为稳定性”。

### 2. 与普通 LLM agent 的区别

普通 LLM agent 往往表现为：

- 以 prompt 为中心；
- 依赖上下文窗口；
- 通过工具调用完成短链路任务；
- 缺少显式的环境状态估计。

持续交互智能体则更接近：

- 具备显式或隐式 belief state；
- 能在多轮交互中维持任务上下文；
- 有长期记忆与状态压缩机制；
- 能处理延迟反馈、不可逆动作与外部扰动。

## 二、最小系统结构

一个最小的持续交互智能体通常包括以下模块：

- 感知接口（perception interface）
- 状态估计器（state estimator）
- 世界模型（world model）
- 任务规划器（planner）
- 策略/控制器（policy/controller）
- 记忆系统（memory system）
- 工具执行层（tool executor）
- 审计与回滚层（audit and rollback layer）

这意味着它不是单模型对象，而是一个分层系统。

## 三、形式化视角

在部分可观测环境（Partially Observable Markov Decision Process, POMDP）下，可用 belief state 记持续交互状态：

$$
b_t = \eta(b_{t-1}, a_{t-1}, o_t)
$$


其中：

- \(b_t\) 是时刻 \(t\) 的信念状态；
- \(o_t\) 是观测；
- \(a_{t-1}\) 是前一动作；
- \(\eta\) 是信念更新算子。

若再引入世界模型，可进一步写为：

$$
\hat{b}_{t+1} = f_\theta(b_t, a_t), \qquad a_t \sim \pi_\phi(a \mid b_t, g_t)
$$


其中：

- \(f_\theta\) 是世界模型或动态预测器；
- \(\pi_\phi\) 是策略；
- \(g_t\) 是任务目标或子目标。

## 四、核心问题

### 1. 状态到底放在哪里

持续交互系统最关键的问题之一是：状态是放在上下文窗口、外部记忆、显式数据库、隐变量还是工具环境中。

可选设计：

- **上下文内状态**：实现简单，但长度受限，漂移严重；
- **外部记忆状态**：可检索、可持久化，但读写协调复杂；
- **隐式潜变量状态**：适合世界模型，但可审计性弱；
- **显式结构化状态**：便于控制与约束，但构建成本高。

### 2. 世界模型要学到什么程度

并不是所有智能体都需要高保真世界模型。应根据任务分层：

- 文本工具型代理：更需要任务图与工具后果模型；
- 机器人/物理系统：需要动作后果预测与安全边界估计；
- 科研代理：需要实验流程、误差传播和知识更新机制。

### 3. 规划深度与计算预算如何平衡

交互式系统中的规划可分为：

- 单步反应式；
- 短视域规划；
- 树搜索；
- 轨迹优化；
- 分层计划。

规划越深，理论上越可能找到更优行动；但计算延迟、模型误差累积和实时约束会快速抬升。

## 五、系统结构模板

### 1. 感知—状态—规划—执行闭环

推荐将系统拆成四级：

1. **感知层**：读入文本、图像、传感器、日志或数据库结果；
2. **状态层**：维护 belief、记忆索引、任务图与环境摘要；
3. **决策层**：进行子目标分解、工具选择、行动排序；
4. **执行层**：调用 API、数据库、仿真器、机器人执行器或文档系统。

### 2. 世界模型在其中的位置

世界模型可承担三类功能：

- **预测器**：预估动作后果；
- **模拟器**：生成候选未来轨迹；
- **压缩器**：把长历史压缩为低维潜在状态。

### 3. 持续学习接口

若系统要长期运行，还需定义更新通道：

- 在线记忆更新；
- 经验回放（experience replay）；
- 安全过滤后的偏好更新；
- 周期性离线再训练。

## 六、失败模式

### 1. 任务漂移

系统在长交互中忘记原始目标，转而优化局部代理目标。

### 2. 记忆污染

错误中间结果被写入长期记忆，随后被反复检索和放大。

### 3. 世界模型幻觉

模型对环境动态过度自信，在未验证情况下执行高风险动作。

### 4. 工具依赖错配

智能体形成“只会调用工具”的假象，但不理解工具适用域和失败边界。

### 5. 反馈延迟下的信用分配失败

长时任务中，成功或失败无法准确追溯到早先哪个决策节点。

## 七、评测指标

持续交互智能体不能只看单轮答案正确率。应至少补充：

- 长时任务完成率（long-horizon task success rate）
- 子目标一致性（subgoal consistency）
- 状态追踪准确率（state tracking accuracy）
- 记忆写入/读取有效率
- 工具调用正确率与恢复率
- 规划成本与时延
- 回滚成功率
- 分布外扰动下的鲁棒性

若存在物理执行或系统副作用，还应统计：

- 安全约束违例率
- 不可逆错误率
- 人工干预频次
- 审计追溯完整度

## 八、与多智能体的接口

持续交互智能体一旦扩展为多智能体系统，额外问题立即出现：

- 局部世界模型与共享世界模型如何协同；
- 通信带宽有限时，什么信息值得共享；
- 角色分工是否稳定；
- 个体策略更新是否破坏群体收敛。

因此，多智能体持续交互通常需要：

- 分层任务图；
- 显式通信协议；
- 共享记忆或黑板系统；
- 局部信用分配与全局绩效评估。

## 九、研究切口

### 适合博士生的方向

1. **基于世界模型的长时任务智能体架构**：研究外部记忆、潜在状态与规划器的耦合。
2. **可审计持续交互智能体**：将 trace、因果链、回滚点与策略版本管理纳入统一框架。
3. **多智能体共享世界建模**：分析局部模型、全局模型与通信压缩的权衡。
4. **高风险环境下的安全规划与执行壳**：把控制屏障函数（Control Barrier Function, CBF）、规则约束或安全审查器嵌入 agent loop。
5. **科研智能体的实验闭环**：围绕文献检索—假设生成—仿真/实验—结果分析—写作回流构建可复现实验链。
