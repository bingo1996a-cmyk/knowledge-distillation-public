# 参数高效微调（PEFT）中的路由、多 Adapter 组合与合并

## 1. 问题背景

参数高效微调（Parameter-Efficient Fine-Tuning, PEFT）已经从"单任务加一个 Adapter"发展到"多任务、多领域、多租户"场景。此时关键问题不再只是能不能微调，而是：

- 多个 Adapter 如何共存；
- 推理时怎样选择或路由到合适 Adapter；
- 不同 Adapter 能否合并；
- 组合后性能与成本如何权衡。

## 2. 路由（Routing）

路由问题本质上是在输入到达时决定调用哪一组适配参数。常见方式包括：

1. **任务标签路由**：按任务 ID 直接选择；
2. **输入感知路由**：根据输入语义或领域特征自动选择；
3. **门控网络路由**：学习一个 gating module；
4. **层级路由**：不同层使用不同 Adapter 组合。

## 3. 多 Adapter 组合

### 3.1 串联

将多个 Adapter 顺序接入，优点是表达能力强，缺点是推理开销增加。

### 3.2 并联

并行输出后再加权合并，适合多源知识融合。

### 3.3 稀疏激活

只激活少量 Adapter，减少时延与显存占用。

## 4. 合并（Merging）

合并的目标是把多个任务或多个 LoRA 权重融合为一个更紧凑对象。主要方法包括：

- 线性加权；
- 任务向量（task vector）叠加；
- 稀疏合并；
- 约束型合并，避免灾难性干扰。

## 5. 合并的风险

- 任务冲突；
- 领域漂移；
- 某些任务退化而总体分数看似上升；
- 推理路由和训练路由不一致。

## 6. 评价指标

- 单任务性能
- 多任务平均性能
- 最差任务性能
- 显存与时延成本
- 可维护性与回滚成本
