# 分词（Tokenization）、蒸馏（Distillation）、量化（Quantization）与推理优化（Inference Optimization）

## 1. 这页的位置

这不是某一种模型架构页，而是大模型工程里最关键的“效率与部署”页。它解释四个问题：

1. 文本如何变成 token
2. 大模型如何压缩到更小模型
3. 权重与激活如何低比特化
4. 推理如何真正跑快、跑稳、跑便宜

## 2. 分词（Tokenization）

> **页面关系**：本节的 tokenization 属于工程概览，仅简述基本概念和核心权衡。分词的经济学视角和技术深度讨论请转至：
> - [分词经济学、上下文利用率与多语言扩展](./tokenization-economics-context-utilization-and-multilingual-scaling.md) — 主文件
> - [分词、字节级建模与多语言效率](./tokenization-byte-level-modeling-and-multilingual-efficiency.md) — 字节级/子词技术对比

### 2.1 为什么需要分词

神经网络不能直接处理原始字符流。必须先把输入序列映射到离散 token，再映射到嵌入向量。

### 2.2 常见方法

- 字符级（character-level）
- 词级（word-level）
- 子词级（subword-level）

现代大模型主要使用子词级方案，如：

- Byte Pair Encoding（BPE）
- WordPiece
- Unigram LM tokenizer

### 2.3 分词的权衡

- 词表过大：embedding 矩阵大，稀疏性强
- 词表过小：序列变长，推理代价上升
- 跨语言任务：不同语言的 token efficiency 差异明显

因此，tokenization 并不是前处理小问题，而会直接影响：

- 训练稳定性
- 长上下文效率
- 多语言表现
- token budget 成本

## 3. 蒸馏（Knowledge Distillation）

蒸馏的核心思想是：用大模型教师（teacher）指导小模型学生（student），使学生在更低成本下模仿教师行为。

最经典蒸馏目标之一：

$$
L = (1-\alpha)L_{hard}+\alpha T^2 KL(p_T^{teacher}\|p_T^{student}).
$$

其中 $T$ 为温度参数。

### 3.1 蒸馏的类型

- logits distillation
- feature distillation
- attention distillation
- response / reasoning distillation

### 3.2 在大模型中的意义

- 轻量模型部署
- 边端模型适配
- 特定领域专用模型
- 思维链或工具使用能力迁移

## 4. 量化（Quantization）

量化是把高精度浮点数映射到低比特表示，例如 FP16、BF16、INT8、INT4。

### 4.1 为什么有效

- 减少显存占用
- 提升吞吐
- 降低带宽压力

### 4.2 两类主要路径

- 训练后量化（Post-Training Quantization, PTQ）
- 量化感知训练（Quantization-Aware Training, QAT）

### 4.3 关键难点

- 激活异常值（outlier）
- 小模型与大模型对量化敏感度不同
- attention / KV cache / normalization 层不一定同样稳健

## 5. 推理优化（Inference Optimization）

> **页面关系**：本节是推理优化的工程概览，目的是让读者建立"推理优化包含哪些组件"的全局认知。详细讨论请转至 04 层系统文件：
> - [推理与服务化部署：Serving、KV Cache、推测解码与连续批处理](../04-systems-engineering/serving-kv-cache-speculative-decoding-and-continuous-batching.md) — 主文件

推理优化不是单一技巧，而是一整套系统工程：

- KV cache
- paged attention
- continuous batching
- speculative decoding
- prefix caching
- operator fusion
- tensor parallel / pipeline parallel / expert parallel

### 5.1 生成式推理的瓶颈

自回归推理的主要成本在：

- memory bandwidth
- attention over long context
- token-by-token serial dependency

### 5.2 几类常见优化

1. **缓存**：复用历史 key/value
2. **批处理**：提高设备利用率
3. **推测解码**：用小模型草拟，再由大模型验证
4. **算子融合**：减少 kernel launch 开销
5. **模型并行**：跨设备扩展大模型

## 6. 四者之间的关系

- tokenization 决定输入表示与序列长度
- distillation 决定模型规模与知识迁移
- quantization 决定参数与激活的压缩方式
- inference optimization 决定部署效率与服务质量

它们共同构成“大模型从训练完成到可用系统”的中间层。

## 7. 常见误区

1. **误区：tokenization 只是分词器问题。**  
   实际上它决定 token 长度、词表结构、跨语言效率与成本。

2. **误区：量化就是无损压缩。**  
   不成立。量化一定伴随信息损失，只是要控制损失。

3. **误区：蒸馏只适合分类模型。**  
   现代蒸馏已广泛用于大模型、推理链与多模态系统。

4. **误区：推理优化只是工程实现。**  
   实际上它已反过来影响模型设计，如长上下文架构与解码策略。
