# 大语言模型：预训练、尺度扩展、后训练与测试时计算

## 1. 概念边界

本页不是"大语言模型（Large Language Model, LLM）是什么"的入门页，而是把 LLM 作为一个完整训练与推理体系来组织：

- 预训练（pretraining）；
- 尺度扩展（scaling）；
- 后训练（post-training）；
- 测试时计算（test-time compute）；
- 工具调用与 agent 化接口。

它起到把 [大语言模型](./large-language-models.md)、[预训练、微调与后训练](../04-systems-engineering/pretraining-and-post-training.md)、[后训练、对齐与偏好优化](../04-systems-engineering/post-training-alignment-and-preference-optimization.md) 三页进一步打通的作用。

## 2. 训练总流程

可将 LLM 的生成过程理解为条件语言建模：

$$
P(x_1,\dots,x_T)=\prod_{t=1}^{T} P(x_t \mid x_{<t})
$$

一个现代 LLM 系统通常经历：

1. tokenizer 设计；
2. 大规模语料清洗与混配；
3. 自回归预训练；
4. 指令微调（instruction tuning）；
5. 偏好优化与对齐；
6. 工具接入、路由、检索与推理系统集成；
7. 测试时计算与评测驱动迭代。

## 3. 预训练：学什么

预训练阶段主要解决三个问题：

- 学语言统计规律；
- 学世界知识与模式压缩；
- 学任务通用表示与跨任务迁移能力。

预训练的核心变量不是单一参数量，而是：

- 语料质量；
- 数据混配策略；
- tokenizer 适配度；
- 架构与上下文长度；
- 训练稳定性。

## 4. 尺度扩展：为什么大模型出现能力跃迁

工程上更可靠的说法不是"突然涌现"，而是：随着模型、数据、上下文和训练计算同步扩展，某些任务能力会跨过阈值，从不可用变为可用。

典型观察包括：

- 长上下文提高跨段依赖处理能力；
- 更大模型提高零样本与少样本泛化；
- 数据质量比盲目扩大数据量更重要；
- 后训练对最终可用性影响巨大。

## 5. 后训练：把语言模型变成可用系统

后训练不只是"让模型更礼貌"。它至少承担四类功能：

- 指令跟随；
- 偏好对齐；
- 领域适应；
- 工具调用与可控推理。

现代路线包括：

- supervised fine-tuning；
- preference modeling；
- RLHF / RLAIF；
- DPO / IPO / ORPO 一类直接偏好优化；
- tool-augmented post-training；
- evaluation-driven iteration。

## 6. 测试时计算：能力不只来自参数，也来自推理预算

测试时计算（test-time compute）研究在部署阶段通过更多步骤、更多候选、更多工具调用或更长思维预算提升性能。它包括：

- self-consistency；
- search / tree-of-thought；
- verifier-guided reranking；
- external tool execution；
- adaptive compute allocation。

一个更完整的系统目标不是：

- 单次前向就解决一切，

而是：

- 在给定时延、成本、风险约束下，动态分配推理预算。

## 7. 系统结构

现代 LLM 系统更接近下面的层次：

`base model -> post-trained assistant -> retrieval/tool layer -> routing/cache layer -> policy/approval layer -> monitoring/audit layer`

这意味着"模型能力"与"系统能力"必须区分：

- 模型能力来自参数、数据和训练；
- 系统能力来自工具、路由、记忆、权限与治理。

## 8. 常见失败模式

- 预训练数据污染与泄漏；
- 指令微调导致能力遗忘；
- 偏好优化过强导致 reward over-optimization；
- 测试时计算增加但没有可靠 verifier；
- 工具调用成功率高但事实正确率不高；
- 长上下文并不等于长程推理真正可靠。

## 9. 评测框架

### 9.1 模型层

- perplexity；
- downstream task score；
- context length robustness；
- calibration。

### 9.2 系统层

- tool success rate；
- groundedness；
- task completion rate；
- cost-latency-quality frontier；
- approval / rollback behavior；
- safety / policy violation rate。

### 9.3 推理层

- pass@k；
- verifier agreement；
- adaptive compute gain；
- failure recovery rate。

## 11. 研究切口

- 预训练与后训练之间的能力分工如何重新划分；
- 如何度量 test-time compute 的真实收益而非 benchmark 偶然增益；
- 如何把 verifier、tool use 与可审计推理整合为统一系统；
- 如何从"语言流畅"转向"任务完成 + 证据可核验 + 风险可控"。
