## 定位

这页讨论的不是"模型会不会推理"这一抽象问题，而是从**系统工程与治理视角**讨论：当系统需要多步推理时，如何通过 reasoning trace 的记录与审计、verification loop 的闭环以及 deliberate inference 的预算管理，使推理过程可审查、可回放且可验证。

## 一、基本思想

### 1. 推理不是一次性输出，而是中间状态演化

很多复杂任务需要先构造候选中间步骤，再筛选、修正与验证。reasoning trace 就是对这些中间步骤的显式记录。

### 2. verification loop 把"生成"与"审查"分开

单纯生成往往不够可靠。verification loop 强调：

- 先生成候选；
- 再检查逻辑、约束、证据和工具返回；
- 若失败则修正或回滚。

### 3. deliberate inference 强调预算化思考

不是所有问题都需要长推理链。更合理的系统会根据任务难度、风险与成本动态决定推理深度。

## 二、为什么这条线重要

- 它连接大语言模型与 runtime governance；
- 它连接 test-time compute 与 verifier / search；
- 它为高风险系统提供"过程可审查"的基础。

## 三、常见结构

- self-consistency
- tree / graph search over reasoning states
- verifier-guided reranking
- tool-verified intermediate steps
- budget-aware adaptive compute
