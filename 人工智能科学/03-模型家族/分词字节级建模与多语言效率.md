# 分词、字节级建模与多语言效率

## 1. 为什么分词是大模型的根问题

大语言模型（Large Language Models, LLMs）并不是直接读取“文字意义”，而是先把文本映射成 token 序列。分词策略决定了：

- 序列长度；
- 词形覆盖；
- 多语言共享方式；
- 推理成本；
- 稀有词与拼写变体的处理方式。

因此，tokenization 不是实现细节，而是模型表达与效率的基础设施。

## 2. 常见分词单位

### 2.1 单词级

优点：语义直接。  
缺点：词表爆炸、未登录词严重。

### 2.2 子词级

代表方法：

- 字节对编码（Byte Pair Encoding, BPE）
- WordPiece
- Unigram LM

优点：

- 在词表规模与覆盖率之间取得平衡；
- 对复合词、低频词更友好。

### 2.3 字符级与字节级

字节级建模把输入统一到更底层编码空间，优点是：

- 真正多语言；
- 不依赖人工分词边界；
- 能更稳地处理罕见字符与编码差异。

代价则是：

- 序列更长；
- 上下文建模压力更大；
- 推理成本提高。

## 3. token 效率与上下文预算

同样的文本内容，不同 tokenizer 会产生不同 token 数。token 数越多：

- 训练计算量越高；
- 长上下文窗口消耗越快；
- 检索增强系统中 chunk 策略会随之变化；
- 推理费用与延迟也会增加。

因此，分词直接影响“token 经济性”。

## 4. 多语言建模的难点

多语言系统中，一个 tokenizer 需要在以下目标间折中：

- 高频语言效率；
- 低资源语言覆盖；
- 跨语言共享子词；
- 对形态复杂语言的适配；
- 对中文、日文、阿拉伯文等脚本差异的兼容。

如果设计不当，会出现：

- 某些语言 token 数远高于英语；
- 训练资源分配不公平；
- 多语言性能被高资源语言挤压。

## 5. 字节级建模何时更值得

字节级方案更适合：

- 极端多语言环境；
- 噪声文本与代码混合语料；
- 需要强鲁棒性的 OCR/日志/网页场景；
- 研究统一表征而非极限效率时。

但若场景重视吞吐与商业推理成本，往往仍需在子词与字节级之间做精细平衡。

## 6. 与蒸馏、量化、推理优化的关系

tokenization 会影响：

- KV cache 占用；
- speculative decoding 效益；
- batching 效率；
- 检索增强的 chunk 划分；
- 微调时的有效样本长度。

因此它不能孤立考虑，而应与 serving 栈联合设计。
